# T-2569: corpus gap: T-2557 gateway WARN misclassifies parallelGateway as unrepresentable decision

## Context

Found compiling 832's pair-draft #2 dispatch-loop.bpmn (T-2568): the Pass-4 gateway WARN (T-2557) fires on `agt_5_fan`/`agt_10_join` (parallelGateway) with the same text as exclusive gateways — "decision semantics are not representable in AEF task skeletons … surfaced here, not applied". Both clauses are wrong for parallel gateways: (a) a fork/join has NO decision semantics (all branches taken unconditionally), and (b) the parallel structure IS applied — the fork's 3 workers emit as siblings with identical `related_tasks` (same nearest-task predecessor, no cross-ordering) and the join fans all branches back into the successor's `related_tasks`. Only EXCLUSIVE gateway conditions are genuinely lossy. Also noisy: a join with a single outgoing edge WARNs about "branches" that aren't branches. Class: WARN-text/classification accuracy, sibling of the T-2557 detector itself (which stays correct for exclusiveGateway).

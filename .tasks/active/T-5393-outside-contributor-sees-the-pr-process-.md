# T-5393: Outside contributor sees the PR process in their own PR: a process comment with a public link to the workflow map

## Problem Statement

An outside contributor never sees our PR process. The workflow map (aef-github-pr-intake) lives in Watchtower (LAN only) and in our task files (T-5391); on PR #116 the contributor saw only CI results. Operator 2026-11-24: the process explanation and a link to the map must be part of the PR comments. Research: `docs/reports/T-5393-contributor-pr-journey.md`.

## Assumptions

- The contributor cannot reach anything behind our LAN (Watchtower, .context/, task files).
- GitHub renders Mermaid in Markdown, so a generated public map page is possible.

## Open Questions

- **IW-1: Who posts the process comment and its step updates: a standing routine rule (sync cron) or an operator runme per post?**
- **IW-2: Where does the public map live (proposed: generated `docs/contributing/pr-workflow.md`, Mermaid, linked on bleeding-edge)?**
- **IW-3: One sticky comment edited per step, or one comment per step?**

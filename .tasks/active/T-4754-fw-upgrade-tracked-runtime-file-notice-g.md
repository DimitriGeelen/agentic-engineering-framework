## RCA

**Symptom:** ring20 (be.19, sidecar 13c2c3bf) ran `fw upgrade` with 214 tracked runtime files under `.context/working`; the T-4701 notice listed all 214 paths one per line and then one `git rm --cached` command 214 paths long. Correct (T-4701 WORKS), but not reviewable: nothing said *what kind* of files they were before asking the operator to untrack them.

**Root cause:** `lib/upgrade.sh:3286` (T-4701) prints `"${_wk_paths[@]}"` verbatim; there was no summarisation step between `fw_working_tracked_runtime` (`lib/working-gitignore.sh:152`) and the command. T-4701 was designed against TermLink's case (one 551 MB log), where a flat list is the best output.

**Why structurally allowed:** the T-4701 bats exercised one tracked file only; output scaling with the number of paths was never a tested property.

**Prevention:** `fw_working_group_tracked` is a pure function with its own bats (`tests/unit/t4754_tracked_runtime_grouped.bats`) pinning counts, order and labels on a mixed fixture (subdirectory + glob rule + exact-name file), plus an end-to-end leg that runs the printed command and checks exactly those paths are untracked.

### 2026-10-26 — what the grouped summary replaces
- **Chose:** the grouped summary replaces the one-path-per-line list; the `git rm --cached` command stays complete (it is the full list). Groups: a path under a subdirectory of `.context/working` groups as `<that first-level dir>/*`; a top-level file groups under the first glob rule it matches (`*.log.*` → `.context/working/*.log.*`); an exact-name rule (or a glob group of one) shows the path itself. Every line is `N x <label>`, largest first, ties by label.
- **Why:** 214 lines of list plus a 214-path command is two copies of the same unreviewable thing; the counts answer "what kind of files are these" and the command answers "which exactly".
- **Rejected:** keeping the full list below the summary (doubles the noise the peer reported); grouping only by directory (all top-level files would lump into one `.context/working/*` group, hiding logs vs pid files).

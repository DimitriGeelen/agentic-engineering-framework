# T-5236: Missing hubs.toml profile: keep retrying, and remediate — exact fix for the sender, one operator notice per user and hub (pending + approvals, runme where one command fixes it), auto-resolve when the retry delivers, daily report after 7 days

## Context

<!-- All four parts are required before source edits (T-4907). Plain language; link design docs for substantial tasks. -->
**Background / trigger:** Operator ruling 2026-11-18, question 4 of 5: keep retrying a send that fails because the sender has no hubs.toml profile for the target hub (option 1). Asked "can we also initiate remediation action in some way", the operator chose the four remediation steps (option 1). Origin: 1409's design session had no ring20 profile (010 T-3797). T-5141 (be.58) now names the reason: "no hubs.toml profile for <hub>: no address or credential for this user" (lib/sidecar/termlink_transport.py:235).

**Problem / hypothesis:** A send with no profile retries quietly. Nobody is told what fixes it. Adding a profile is a credential change on a host, which is the operator's to do, and nothing reaches the operator. TermLink can repair an existing profile (`termlink fleet reauth <hub>`, `--bootstrap-from`) but has no command that creates a missing one.

**Goal:**
1. The sender's "NOT delivered" detail names the hub, the user, and the exact fix: `termlink fleet reauth <hub>` when the profile exists but its secret is broken, or the hubs.toml lines to add when it is missing.
2. ONE operator notice per (user, hub) pair, never one per retry, in `fw operator pending` and the Watchtower approvals page: "user X on host Y has no profile for hub Z; N messages waiting; fix: …". Where the fix is one command, it comes as a prepared runme.
3. When a retry later delivers to that hub, the notice resolves itself.
4. A pair still unresolved after 7 days is reported by the daily check.

The retry behaviour itself does not change, and agents never write credentials.

**Expected outcome:** A missing profile reaches the operator once, with the fix ready. Once fixed, the waiting messages go out on their own, and nothing is forgotten.

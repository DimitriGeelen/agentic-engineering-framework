## RCA

**Symptom:** `fw handover --commit` and then a manual `git push` both returned HTTP 403
from origin, after ~10 successful pushes to the same remote with the same credential in
the same session.

**Classification (AC-1), by evidence rather than by retry:**
- authenticated `git ls-remote origin refs/heads/master` → exit 0. **Read works.**
- `curl` on the server root → HTTP 200. **Server up.**
- credential unchanged (no rotation, no remote edit) — verified by inspecting `git
  remote -v` with the token masked.
- ⇒ write-specific, not an auth-wholesale failure and not an outage.

**Root cause: NOT ESTABLISHED. Recording that plainly rather than dressing up the retry.**
The next push, ~90 seconds later with nothing changed, succeeded. That makes it transient
by observation, which is a description, not a cause. The most plausible mechanism is a
server-side write lock — OneDev runs a `PushRepository` mirror job for this repo (the
handover output names it: "Skipping github (mirrored from origin via PushRepository)"),
and a concurrent mirror/GC job holding a write lock would present exactly as a read-OK,
write-403. **That is a hypothesis I did not test** — confirming it needs OneDev server
logs, which are outside this repo. Filed as a hypothesis so the next occurrence starts
from evidence instead of from scratch.

**Why structurally allowed / what the framework did right:** nothing was lost. The
handover push failure was non-blocking, reported loudly, and named the manual recovery
("Some pushes failed. Run 'git push' manually after resolving."). Parity was restored to
0 on both refs.

**Prevention:** the residual gap is small and real — `fw handover --commit` does not
retry a transient push failure, so every such 403 leaves an unpushed commit and depends
on the agent reading the output and acting. Given "do not end a session with unpushed
commits" is a standing rule, a bounded retry (2 attempts, short backoff) would close it.
Recorded as an observation rather than built here: this task's scope is the incident, and
changing the handover push path is a separate deliverable with its own blast radius.

# T-2570: corpus gap: parallelGateway note fires WARN on clean balanced fork/join (occasion-level FP)

## Context

832's position (rail offset 103, recorded in their T-217 Decisions) arrived crossing the T-2569 ship message: T-2569 fixed the parallel-gateway WARN's *vocabulary* (concurrency terms, no false loss claim) but the *occasion* is still wrong — in 832's validator a well-formed balanced fork/join emits ZERO findings; `_check_parallel_gateways` fires only on smells. AEF WARNing on clean balanced structure is a false positive at the WARN level. Their taxonomy (the alignment target): **W-PGW-CONDITION** (condition on a fork edge → the condition specifically is ignored, "did you mean exclusiveGateway?"), **W-PGW-NOOP** (in≤1 ∧ out≤1 — neither forks nor joins), **W-PGW-UNBALANCED** (fork without join or vice versa — branches never reconverge). Balanced fork/join matches none → clean. Their rejected alternatives: softened shared text (still wrong-kind + still fires on clean); synthetic per-fork WARN (re-adds the FP).

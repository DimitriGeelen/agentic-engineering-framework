**Symptom:** in 055 (2026-10-26 16:39) a scratch test exported TMUX_TMPDIR to isolate itself, ran a bare `tmux kill-server`, and killed the shared tmux server that every live agent session ran on. Here the same command passed the destructive-command gate unblocked (reproduced: 7 of 7 blocked shapes in tests/unit/t4783_tier0_tmux_kill.bats were red before the fix).

**Root cause:** agents/context/check-tier0.sh had no rule for tmux at all. The kill-by-name rules (T-3640, check-tier0.sh:341-346) cover pkill/killall only, and the keyword prefilter (check-tier0.sh:142) had no tmux term, so a tmux kill exited on the fast path before any pattern ran. The danger is non-obvious: inside tmux the shell has TMUX set, and tmux prefers TMUX over TMUX_TMPDIR when picking the server, so isolating via TMUX_TMPDIR does not isolate a kill; only an explicit -S/-L does.

**Why structurally allowed:** the gate is a denylist of typed spellings. Each new destructive shape is added after an incident (pkill -f came from 055 P-006 the same way). Nothing enumerates "commands that act on shared host-wide state", so a server kill that reaches every session was never a candidate.

**Prevention:** the new PATTERNS entry (after the KILLALL -r rule) plus `kill-se` in the prefilter; tests/unit/t4783_tier0_tmux_kill.bats pins 055's blocked and allowed shapes, so removing either the pattern or the prefilter term goes red. T-4781 (one server per project) limits the reach of any kill this rule misses.

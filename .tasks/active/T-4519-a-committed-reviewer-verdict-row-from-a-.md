**Symptom:** on 832, two committed green rows (V-20261020-6ba9cb1c, V-20261020-5a4ff53f) from
claude review workers SIGTERMed after committing made `fw audit` FAIL permanently and blocked every
push; the only exit (`acknowledge`) needs a completed fixing task in the consumer's own task tree.

**Root cause:** `lib/verdict_ledger.py` `audit()` grades every `_row_fault` as FAIL unless a
committed acknowledgement covers it (`_ack_for`). `_completion_fault` returns `worker-failed` for a
green whose runtime-signed completion has exit != 0 — a fully attested, truthful record of a review
that did not finish — and audit treats it exactly like a forged row. The claude worker commits its
own row (`_cli` record → `record_and_commit`, T-3940) before its exit is known, so any kill between
that commit and the exit produces such a row, and the append-only ledger can never drop it.

**Why structurally allowed:** the T-3581 audit treats every non-counting row as forgery-shaped.
`t3580_round3_test.py::test_a_green_from_a_worker_that_exited_non_zero_does_not_count` asserted only
that the row does not count, never what audit does with it afterwards, so the permanent push block
was invisible until a consumer hit it.

**Prevention:** `tests/unit/test_t4519_worker_failed_row.py` pins the audit grade of a worker-failed
row (WARN, exit 3, never counts), the guard that any other fault on it still FAILs, the
supersede-by-later-verdict path, and the provisional (in-flight) grade.

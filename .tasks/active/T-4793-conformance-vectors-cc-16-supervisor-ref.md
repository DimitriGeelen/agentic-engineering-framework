### 2026-10-27 — how the runner tells the real path from a silent equivalent
- **Chose:** the adapter declares the variants it runs by the equivalent in an optional `adapter.equivalent_routes` set (`"CC-16/supervisor-refusal"`). For a declared route every step result must carry a non-empty `"equivalent"`, else the variant fails ("taken silently"); the string is named in the case result. An undeclared adapter is judged on the steps as today. An `"equivalent"` on a variant that offers none fails.
- **Why:** the agreed contract (msg to ring20 in reply to dd8fe9b8) asks for both "a matching result without `equivalent` fails" and "a real-path backend returns no `equivalent` and is judged as today". From the step result alone the two are the same result, so the runner needs the backend to say which route it took. A declaration keeps the closed n/a list and adds no `requires` or vocabulary capability.
- **Rejected:** (a) inferring the route from the result alone — a silent equivalent then passes, which the contract forbids; (b) a new vocabulary capability such as `worker_refusal` — a 3-way spec amendment (§6.6 closed n/a list); (c) per-variant n/a — breaks N2 for a transition-subject case.

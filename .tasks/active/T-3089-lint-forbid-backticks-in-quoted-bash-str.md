# T-3089: Lint — forbid backticks in quoted bash strings

## Context

T-3086 was a fork bomb caused by Markdown-style backticks inside a double-quoted
`FW_CONFIG_REGISTRY` element in lib/config.sh. bin/fw sources config.sh on every
invocation, so every `fw` call executed the backticked command, which sourced
config.sh again. Four kernel OOM crashes of the host in 22 hours.

The sibling guard tests/lint/no-backticks-in-inline-python.bats (T-2707) already
covered this defect shape — but only inside double-quoted `python3 -c "..."` blocks.
A backtick in a plain bash string was unguarded. This closes that half (Level C).

Detection uses shellcheck's SC2006 rather than a hand-rolled scanner: the first draft
of this guard was a bash state machine and false-positived 25 times on apostrophes in
comments, heredocs, and Python files carrying a .sh extension. shellcheck parses the
real grammar. Measured at authoring time: 199 tracked bash files, zero SC2006
violations — the guard starts green.

A second, narrower assertion (pure Python, runs without shellcheck) checks that
registry descriptions contain no backticks, `$(` or `${`, since all three expand on
source and the next instance is as likely to be a `$(...)` as a backtick.

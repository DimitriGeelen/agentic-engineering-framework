# T-5198: Watchtower approvals cold page, next three costs after T-5186: ref-dependent git log (~7 s), inception_handoff_blockers shell calls (~5 s), task frontmatter parsing (~4.4 s)

## Context

<!-- All four parts are required before source edits (T-4907). Plain language; link design docs for substantial tasks. -->
**Background / trigger:** After T-5186's slices A/B/C (T-5194/5/6), a cold approvals page still costs ~27 s at ~5,200 tasks. T-5196's measurements rank the rest:
- ~7 s: 6 ref-dependent `git log` calls in lib/verdict_ledger.py.
- ~5–6 s: 47 `bash -c` subprocesses from `inception_handoff_blockers`.
- ~4.4 s: task frontmatter YAML parsing in `get_all_task_metadata`.

The operator said to proceed as seen fit (2026-11-17).

**Problem / hypothesis:**
- `inception_handoff_blockers` shells out per inception on every cold computation, though its answer depends only on the task file and repo state.
- Frontmatter parsing re-reads every task file whenever the whole-corpus cache's TTL or signature expires, although only a few files change between requests.

**Goal:** The two cheaper, lower-risk items:
- (1) Cache `inception_handoff_blockers` per task (keyed on the task file's mtime and the inputs it actually reads; find them in the code, and when unsure include the git state token), or do its work in-process instead of via `bash -c`.
- (2) Make frontmatter parsing incremental: keep parsed frontmatter per file keyed on (path, mtime_ns, size) in memory, and re-parse only changed files.

Out of scope here: the ledger's `git log` walks (they decide verdicts and need their own design and review), and anything stored on disk.

**Expected outcome:** A cold approvals page drops by roughly the measured ~9–10 s. A page after a few task edits re-parses only those files. No output differs (equivalence tests).

### 2026-11-17 — inception_handoff_blockers: transcribe, not cache
- **Chose:** compute in-process (`_handoff_blockers_from_text`), guarded by a sha256 of the three
  shell functions' text (`_HB_TRANSCRIBED_DIGEST`): while the shell rule is unchanged the
  transcription answers; if it changes, the shell predicate runs as before; if the rule files are
  missing, the check fails closed. Cache key: task file (mtime_ns, size) + (mtime_ns, size) of
  lib/inception-readiness.sh and lib/task-audit.sh.
- **Why:** the predicate reads only the task file (no git, no other file), and an in-memory
  cache alone cannot help a cold process, which is where the ~6 s was. The digest guard keeps
  the shell function the one definition (L-399): a page can never disagree with the gate, even
  before someone updates the transcription; `test_transcription_digest_is_current` then goes red.
- **Rejected:** a per-task cache over the `bash -c` call (no cold gain); a batched single
  `bash` call (still ~6 s of per-line forks inside the shell loop).

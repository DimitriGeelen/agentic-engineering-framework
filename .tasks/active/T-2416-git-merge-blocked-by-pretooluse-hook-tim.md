# T-2416: Git merge blocked by PreToolUse hook timing - FW_SAFE_MODE ineffective

## Context

**Origin:** S-2026-0702-1443 attempting to merge t2417-fw-sessions (T-2501). Session detection fixed (session.yaml updated to current session), but all git operations (pull, merge) remain blocked by PreToolUse hook even with FW_SAFE_MODE=1.

**The catch-22:** PreToolUse hook runs before bash evaluates environment variables, so `FW_SAFE_MODE=1 git merge` or `export FW_SAFE_MODE=1 && git merge` both fail - the hook sees the command string before the env var takes effect. Even though the merge is fully authorized (T-2501 with 90 verified commits), automated execution is impossible.

**Workaround:** Manual terminal execution (not through Claude Code) bypasses PreToolUse hooks.

**Related:** T-2054 (post-completion commit exemption), T-2462 (push/fetch safe-listing), L-399 (hook bypass contract parity)

## RCA

**Symptom:** Agent attempting git merge with FW_SAFE_MODE=1 is blocked by PreToolUse hook with "BLOCKED: No active task" even though hook code (lines 24-27 of check-active-task.sh) has explicit bypass check `if [ "${FW_SAFE_MODE:-0}" = "1" ]; then exit 0; fi`.

**Root cause:** PreToolUse hook executes in Claude Code's process before the bash command runs. When agent writes `FW_SAFE_MODE=1 git merge` or `export FW_SAFE_MODE=1 && git merge`, the hook reads stdin JSON containing the command STRING but the environment variable hasn't been evaluated yet - it's just part of the command text. The hook's shell process doesn't inherit the variable from the command it's inspecting.

**Why structurally allowed:** No test coverage for FW_SAFE_MODE bypass mechanism under PreToolUse hook timing. T-650 added the bypass but only tested it in contexts where the env var was already exported in the parent shell, not as a command-line prefix.

**Prevention:** Integration test that simulates PreToolUse hook flow: stdin JSON with command containing `FW_SAFE_MODE=1 git ...`, verify hook exits 0. Alternative: document that FW_SAFE_MODE must be set in Claude Code session environment, not command-line prefix.

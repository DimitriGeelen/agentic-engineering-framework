# T-100160: create-task.sh interactive prompts hang forever in no-tty contexts

## Context

OBS-086: `create-task.sh` falls back to interactive `read -r` prompts when required fields are missing. In no-tty contexts (harness background tasks, cron, TermLink workers) stdin is a socket that never delivers data, so the process blocks forever — two `fw task create` invocations hung for over an hour on 2026-07-04 (blocked in `unix_stream_data_wait` at the `Owner:` prompt).

## Acceptance Criteria

### Agent
- [x] With stdin not a tty and a required field missing, `create-task.sh` exits non-zero with an error naming the missing flag(s) instead of prompting
- [x] The tty prompt path is preserved — the no-tty guard precedes the first prompt and fires only when stdin is not a tty (structural pin; live-pty test is racy under bats)
- [x] bats regression pins the non-interactive fail-fast behaviour

## RCA

**Symptom:** two background `fw task create` invocations hung >1h, blocked in `unix_stream_data_wait` reading stdin.

**Root cause:** `create-task.sh` prompts interactively (`read -r`) for any missing required field; with a socket/pipe stdin that never delivers, the read blocks forever.

**Why structurally allowed:** the interactive fallback predates non-interactive callers (background dispatch, cron, TermLink workers); nothing checked whether a terminal was actually attached, and a hung background process emits no output to alert anyone.

**Prevention:** `[ ! -t 0 ]` guard fails fast with the exact missing flags; bats pins the no-tty fail-fast, the full-flags path, and the guard-precedes-prompts ordering.

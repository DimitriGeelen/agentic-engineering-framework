**Symptom:** 832 (msg 197ddc3d): three direct-path sends to AEF at ~11:05Z 2026-10-21 were REJECTED with HTTP 401. A later retry got through.

**Root cause:** this is the same defect as T-4560 (ba9eaa5f9). The credential is the bearer token in `.context/sidecar/receiver.token`. Senders read it from the registry's `token_file` at send time (`lib/sidecar/direct.py:170`). `.context/sidecar/watcher/events.jsonl:4422-4423` shows 10:52:14Z `STOP_REQUESTED reason=restart` and then 10:52:15Z `RECEIVER_RESTARTED rc=2 "server exited with 3 before binding"`. `_start_receiver` (`lib/sidecar_cli.py:879`) rewrites the token before spawning the server, and the new server refused because a live rival existed (T-4208). The old receiver stayed live, but `_is_authorized` (`lib/sidecar/http_server.py`, pre-ba9eaa5f9) compared only the token it had read at startup. So the receiver side was stale; the file and the discovery record were current. 832's ~11:05Z sends fall inside the 10:52:15Z–11:15:06Z window, and the "later retry" was after the 11:15Z successful restart loaded the new token. The TermLink session id change (tl-vel6bo4u) was the visible sign of that session restart. It is not a credential the direct path checks.

**Why structurally allowed:** the token had two owners (the file and the receiver's memory) and nothing reconciled them. No test rotated the token under a live receiver (T-4560 RCA).

**Prevention:** T-4560's fix: `_is_authorized` accepts the startup token or the token currently in the file. Also T-4560's tests, plus `tests/unit/test_sidecar_restart_401_t4533.py`, which replays 832's shape through the real `sidecar send` CLI: a rotation with no successful restart, then three sends. Against the pre-fix `http_server.py` (ba9eaa5f9^) it fails with `'REJECTED' == 'RECEIVED'`. On current code it passes.

# T-3359: tests/unit has not completed a single run in 4 nights: bats consumes the whole 7200s ceiling and the pytest leg measures 0 of 201 files

## Context

`agents/audit/unit-suite.sh` runs its two legs **sequentially against one shared
budget**. `_remaining()` (line 51) returns `TOTAL_TIMEOUT - elapsed`, clamped to a
floor of **1**. So when the bats leg burns the whole 7200s and is killed (rc=124),
the pytest leg is invoked as `timeout 1` — one second, for 201 test files.

That is what the nightly reports have been recording, unchanged, for four
consecutive nights (2026-09-08, -09, -10, -11 — all `bats_rc=124 pytest_rc=124`):

```
pytest:  files: 201   tests: 0   failed_count: 0   skipped: 0   exit: 124
```

The pytest leg is not slow. It is **structurally starved**: it can never run while
the bats leg overruns, and the bats leg has overrun every night on record. 201
files of the framework's own unit corpus are unmeasured, and the report renders
that as a leg with zero failures.

This is the T-3302/T-3328 false-signal family again, one layer in: `failed_count:
0` on a leg that was given one second is not a measurement, and nothing in the
report distinguishes "ran, found nothing" from "never got to start".

**Scope fence (one bug = one task).** This task fixes the STARVATION — leg 1 must
not be able to consume leg 2's budget. It does **not** fix the bats leg exceeding
7200s; that is a separate defect (filed separately) and the bats leg will still
time out after this change. The deliverable here is that the pytest leg gets
measured at all, and that a starved leg is legible as starved rather than green.

## RCA

**Symptom.** Four consecutive nightly reports (2026-09-08..11) record
`pytest: files: 201, tests: 0, failed_count: 0, exit: 124`. The framework's
largest unit corpus — 2706 collected tests — has never been measured.

**5 Whys.**

1. *Why does pytest record zero tests?* It is killed almost immediately.
2. *Why is it killed?* It is invoked as `timeout 1`.
3. *Why a 1-second timeout?* `_remaining()` returns `TOTAL_TIMEOUT - elapsed`
   clamped to a floor of 1, and the bats leg had already consumed the full 7200s.
4. *Why could the bats leg consume leg 2's budget?* The two legs run sequentially
   against a single shared window, and leg 1 was handed the whole window with
   nothing held back. There is no reservation — only a floor that keeps the
   arithmetic from going negative.
5. *Why did nobody see it?* The report renders the starved leg as
   `failed_count: 0`, which is indistinguishable from a clean leg. Nothing in the
   schema recorded how much time the leg was given, so "measured nothing" and
   "found nothing" printed the same.

**Root cause.** A shared, unreserved resource consumed in order, where the first
consumer's overrun is silently paid for by the second — and a report schema that
recorded the *result* of each leg without recording the *budget* it was granted,
so the starvation was unobservable in the artefact that exists to observe it.

**Structural change.** The reserve is carved out of leg 1's cap up front
(`_remaining_reserved()`), so starvation is not reachable rather than merely
unlikely. `budget_seconds` is now recorded per leg, so `tests: 0` is always
readable against the time the leg actually had. Both directions are pinned by
mutation-verified tests.

**Method note (worth keeping).** The first version of the starvation test passed
under mutation — the fixture pytest suite was one trivial assertion that completed
inside the 1-second starvation budget, so it demonstrated nothing. The test had
the same defect as the system under test: it could not distinguish "ran" from
"never got to start". Caught only because the assertions were mutation-checked
rather than trusted for being green. The fixture now sleeps past the old floor.

**Not fixed here (deliberately, one bug = one task).** The corpus exceeds its
window: the bats leg needs >7200s on its own, and the pytest leg is measured at
>1800s and still running at the time of writing. This task makes the split fair
and legible; it does not make the corpus fit. Filed separately.

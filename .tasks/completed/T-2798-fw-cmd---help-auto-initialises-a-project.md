# for the captures they were written about, and both invert above the pipe
# buffer. `echo "$out" | grep -q PAT` is NOT SIGPIPE-free — it is SIGPIPE-free
# only while "$out" fits in the 65536-byte pipe buffer. Above that, with an
# early match: echo blocks on the full pipe, grep -q exits, echo takes SIGPIPE,
# pipeline exits 141 under pipefail — the exact failure L-387 exists to prevent.

**Symptom:** An operator's onboarding agent ran `fw doctor --help` in an empty
`/opt/2345-test-install` to confirm the verb existed. Instead of usage text it got
*"Setting up agentic governance for 2345-test-install..."* — a git repo was created
and the framework began vendoring. The run was interrupted mid-vendor, leaving
`.git` + `.agentic-framework/` with no `.framework.yaml`, after which every `fw`
call in that directory failed *"Cannot find framework installation."*

**Root cause:** `bin/fw`'s auto-init branch decides whether a command is
side-effect-free by testing `$1` against an allowlist
(`init|help|-h|--help|version|-v|--version|update|hook|vendor`). A help flag on a
*subcommand* sits in `$2`, so `fw <anything> --help` was never exempt. Under a
non-TTY stdin — every agent-driven invocation — the branch takes the silent path
that inits with defaults and never prompts.

**Why structurally allowed:**
1. **The allowlist models the wrong thing.** It enumerates commands believed
   harmless, when the property that matters is a flag that can appear anywhere in
   the argument vector. An allowlist over `$1` cannot express "any argument is
   `--help`", so it was wrong for every subcommand simultaneously — not an omission
   of one entry but a category error, which is why the bug is uniform rather than
   spotty.
2. **The question was raised and deferred.** T-2769's comment in this very branch
   says: *"Whether a read-only query should trigger it at all is a separate
   question, deliberately not decided here (T-2770)."* The deferral was reasonable
   for the general case; nobody noticed that the specific case of `--help` was not a
   policy question at all.
3. **The blast is invisible at the call site.** Auto-init announces on stderr and
   returns 0, so a caller checking exit status sees success. The only signal is
   prose in a stream agents routinely discard.

**Prevention:** `tests/unit/fw_help_no_autoinit.bats` asserts `--help`/`-h` mutate
nothing across four unrelated subcommands, checking `ls -A` on the temp dir rather
than trusting the exit code. A fourth test asserts auto-init still fires for a real
command, so deleting the branch cannot turn the suite green.

**Not fixed here (own task):** the debris is not recoverable by the tool that
created it. An interrupted `do_init` vendors before writing `.framework.yaml`, and
`.agentic-framework/` without `.framework.yaml` makes every `fw` verb fail — so the
directory cannot be repaired or re-inited with `fw`, only by hand. Whether bare
`fw doctor` (read-only) should auto-init at all remains T-2770.

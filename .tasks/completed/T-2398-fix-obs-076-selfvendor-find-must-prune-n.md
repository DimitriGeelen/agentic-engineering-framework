**Symptom:** The T-2240 self-vendor pre-push gate reports `Self-vendor: would sync 11 file(s) to .agentic-framework/lib/` and blocks every push from the main checkout, even though `diff -rq lib .agentic-framework/lib` shows byte-identical trees. Required `FW_SKIP_SELF_VENDOR_CHECK=1` on every master push (2026-06-14).

**Root cause:** `_self_vendor_libs` (and siblings `_self_vendor_agents`, `_self_vendor_web`) scan the SOURCE tree with `find "$FRAMEWORK_ROOT/<dir>" -type f \( -name "*.sh" -o -name "*.md" ... \)` and never prune `node_modules` / `__pycache__` / `.git`. So they pick up untracked third-party files (e.g. `lib/ts/node_modules/{argparse,esbuild,typescript}/README.md`), look for them under `.agentic-framework/lib/ts/node_modules/` (which doesn't exist), and count them as drift.

**Why structurally allowed:** (1) `node_modules` is gitignored/untracked, so it's invisible to `git status` and to a tracked-file diff — the drift only appears in the find-based scan. (2) It's path-dependent: main has `node_modules` (npm install ran in `lib/ts/`), fresh git worktrees don't — so `fw vendor self --dry-run` is CLEAN in a worktree and only FAILs from main. The asymmetry hid it: the audit-side scanner (`audit.sh:1644`) finds from the VENDORED tree (clean of node_modules), so audit never flagged it — only the source-scanning vendor helper FP'd. (3) No test fed a populated node_modules to the helpers.

**Prevention:** (a) prune clause `\( -path '*/node_modules/*' -o -path '*/__pycache__/*' -o -path '*/.git/*' \) -prune -o ... -print` on all three find-based helpers; (b) `tests/unit/t2398_self_vendor_prune.bats` feeds each helper a synthetic tree with node_modules/__pycache__ junk and asserts zero phantom drift, plus positive controls so the prune doesn't mask real drift. The test is the structural counter — without it, a future refactor could drop the prune and the FP returns silently (only visible when someone pushes from a node_modules-populated checkout).

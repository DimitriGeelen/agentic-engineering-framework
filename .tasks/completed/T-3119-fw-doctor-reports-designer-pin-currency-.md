# T-3119: fw doctor reports designer pin currency: WARN when source_origin has a newer tag

## Context

`fw doctor`'s designer check measures EXPOSURE only — vendored sha256 vs
`policy/designer-pin.yaml`. It never asks whether the pin is still the newest
release the origin publishes, so designer-v0.9.0 → v0.11.0 sat unconsumed for
three releases with every instrument green. This task adds the CURRENCY half:
resolve the newest `designer-v*` tag at the pin's own `source_origin:` and WARN
when the pin is behind it. Re-pinning is out of scope (T-3120).

## Acceptance Criteria

### Agent
<!-- Criteria the agent can verify (code, tests, commands). P-010 gates on these. -->
- [x] `fw doctor` resolves the newest `designer-v*` tag at the pin's own `source_origin:` and
      WARNs when it is ahead of `version:`, naming both versions. Silent when the pin is current.
- [x] The check degrades to a distinct, non-failing state when the origin is unreachable —
      an unreachable origin must not read as "pin is current" (T-2916 / L-575: a guard that
      cannot read its input reports the same thing as a guard that found nothing).
- [x] Version comparison is semantic, not lexical — `0.10.0` and `0.11.0` are both ahead of
      `0.8.0`. A string compare puts `0.8.0` ahead of `0.10.0` and inverts the whole check.
- [x] The network call is bounded and cannot hang `fw doctor` on an unreachable origin.
- [x] Covered by bats over a real local git remote with tags — not a mocked `ls-remote` —
      including the ahead, current, and unreachable cases.

**Symptom:** `fw harvest` always reports "No learnings found in project" — the learnings sub-stage of cross-project knowledge leveling has never harvested anything (549 entries match the live 2-space shape, 0 match the 4-space grep). Patterns sub-stage partially blind for the same reason.

**Root cause:** Four grep sites hard-coded a 4-space field indent (`^    learning:` / `^    pattern:`) while the capture path writes 2-space field lines under column-0 list items. Third instance of the indentation-assumption class: T-2672 (resolve.sh emit-indent, from 832's T-295 field report), and the dead audit graduation counter (same file-shape blindness, filed separately per one-bug-one-task).

**Why structurally allowed:** harvest.sh had zero tests; its SKIP output ("No learnings found in project") is indistinguishable from a legitimately empty project, so the dead leg looked like normal operation for its entire life. Nothing cross-checks harvest counts against the store it reads. Surfaced only by T-2667's corpus-map baseline mining, which counted matches at both indents.

**Prevention:** `tests/unit/harvest_indent_agnostic.bats` pins both shapes + mixed files + dedup; the T-2667 map carries the dead-leg honesty note (flips at promotion once this fix lands); the indentation-assumption class now has three recorded instances — grep-by-shape against YAML stores should be indent-agnostic by default.

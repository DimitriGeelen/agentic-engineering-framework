## RCA

**Symptom:** the live AEF sidecar watcher went down at 2026-10-25T13:53:52Z, and once before on 2026-10-21T00:06:53Z. Both times events.jsonl recorded a STOP_REQUESTED whose caller_cwd was a temp t3693 agent root but whose caller_project_root was `/opt/999-Agentic-Engineering-Framework`. Pre-push then FAILed with "Sidecar inbox with nothing to wake it".

**Root cause:** the stop came from an agent-typed cleanup shell, not from the test code. Both e2e tests build their child env from scratch (`_clean_env`, t3693_sidecar_e2e_test.py:73; t3684 wraps it), so they never pass PROJECT_ROOT, and run from a temp root `bin/fw` correctly resolves that root. A Claude Code agent shell in this repo does carry `PROJECT_ROOT=/opt/999-Agentic-Engineering-Framework` in its environment. The 13:53 command was `cd $B/$a && env -i … bin/fw sidecar receiver stop || <fallback>`. Its `env -i` leg failed because a temp agent root has no `bin/fw`, and the fallback ran with the session env. The 10-21 probe ran `/opt/…/bin/fw sidecar receiver stop` straight from the session shell. `bin/fw:281` keeps a valid inherited PROJECT_ROOT ("env wins", T-2391). The T-3285 re-anchor at `bin/fw:368` fires only when `_FW_PATHS_DERIVED_BY` is present, and a session env does not carry it. The CLI then trusts the env first (`lib/sidecar/receiver.py:74` `_root()`), so `cmd_receiver_stop` → `watcher.stop_all()` (`lib/sidecar/watcher.py:1070`) wrote `stopped`, deleted `enabled.json` and SIGTERMed the supervisor of the project named by the env, not the project the command was run in. Reproduced on synthetic fixtures: from `agent/` with `PROJECT_ROOT=live`, `bin/fw sidecar receiver stop` wrote `live/.context/sidecar/watcher/stopped` (rc 0).

**Why structurally allowed:** the sidecar lifecycle verbs had no notion of "the project I am run in". Every state path goes through `_root()`, which ranks env above cwd, and stop/start were not treated differently from read-only verbs. T-4315 already recorded caller_cwd next to caller_project_root on every stop, so each incident was attributable after the fact, but nothing compared the two before acting. The guard tests that existed (test_t3761_e2e_teardown) cover the test's own teardown env, and that env was never the leak.

**Fix:** `fw sidecar start|stop` and `fw sidecar receiver start|stop` refuse (exit 2, naming both roots) when PROJECT_ROOT names one project and the cwd is inside a different one. `--project DIR` is the explicit override and sets the target. In-process callers (unit tests, the supervisor's restart, which runs with cwd = its root) are unchanged.

**Prevention:** tests/unit/test_t4753_sidecar_stop_target_guard.py runs stop, receiver stop, start and receiver start from a fixture agent root with PROJECT_ROOT naming a separate fixture "live" root. It asserts refusal, that no `stopped` marker was written and no STOP_REQUESTED event was appended in "live", and that `--project` and a clean env both act on the agent root. It fails against HEAD's sidecar_cli.py (the stop writes live's marker).

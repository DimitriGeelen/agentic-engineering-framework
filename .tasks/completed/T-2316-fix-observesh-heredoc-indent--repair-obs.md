# T-2316: fix observe.sh heredoc indent + repair OBS-068+069 in inbox.yaml

## Context

Discovered during T-2315 close — `python3 -c "import yaml; yaml.safe_load(open('.context/inbox.yaml'))"` raises `ParserError at line 578` because OBS-068 (line 585) and OBS-069 (line 592) are written with 2-space leading indent (`  - id:`) while OBS-001..OBS-067 are at root (`- id:`). PyYAML interprets the mixed-indent `  - id:` as a nested mapping key under OBS-066's value, which is incompatible with the existing schema.

Root cause: `agents/observe/observe.sh:89-97` heredoc appends with 2-space dash. Existing entries (OBS-001..OBS-067) are at 0-space dash — most likely written by a different code path or normalized at some past point. Mixing the two breaks the parse.

Bug class: silent data corruption. `fw note triage` and `fw note dismiss` use sed-in-place patches that don't load the YAML, so they don't notice the parse error. Downstream consumers that load via PyYAML (audit, watchtower) silently lose the malformed entries.

- [x] Regression: writing a sentinel obs via `fw note` keeps the file parseable

## RCA

**Symptom:** `yaml.safe_load(.context/inbox.yaml)` raises ParserError at line 578.

**Root cause:** `observe.sh:90` heredoc writes `  - id:` (2-space dash). When the file's existing list items are at 0-space dash, appending 2-space breaks YAML structure — the new dash becomes a nested mapping key, not a sibling list item.

**Why structurally allowed:** No regression test exercises a round-trip (write → load → write). `fw note` writes via heredoc, `fw note triage/dismiss` patch via sed — neither path validates the result parses. PyYAML-using consumers fail silently (skip malformed items).

**Prevention:** Bats regression that writes an observation and asserts `yaml.safe_load` succeeds. Aligns the heredoc with the canonical style (0-space dash) so the bug class disappears.

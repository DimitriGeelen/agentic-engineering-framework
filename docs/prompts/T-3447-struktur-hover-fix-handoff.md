## The problem — already measured, do not re-investigate

`site/struktur.html` (generated by `tools/site_build.py`) currently shows **three
disclosure surfaces for one entity**:

| Surface | Trigger | Size at 1440×900 | Pinnable |
|---|---|---|---|
| `#panel` sticky | row hover | 178px fixed | yes (click) |
| `#karte` collapsed | row hover +90ms | 416×165 | no |
| `#karte` expanded | hover the card itself | 416×**868** | no |

Name, type and description appear on all three. The path appears twice.
`Nur diesen Zweig zeigen` appears twice. The only content unique to the collapsed
card is the one-line relation to the run.

Four defects, all measured, all traced:

**1. Entering the card teleports it.** `letzteZeile` is initialised to `0` and
**never assigned** — `imSchirmHalten()` is only ever called with no argument
(`tools/site_build.py:1776`). So `t` collapses to `8`, and `8px` is written to an
element positioned `absolute` (document coordinates) while the `8` came from
`clientHeight` (a viewport measure). Two coordinate spaces mixed.

MutationObserver trace, viewport 1440×900, `scrollY` 3000:

```
tree.mouseover VM-515    top: 3346.7px   h:165   k-mehr hidden
card.mouseenter          top:      8px   h:868   k-mehr shown    ← jumps ~3.3k px up
card.mouseleave ×3
tree.mouseover VM-601    top: 3376.45px  h:185   k-mehr hidden   ← wrong entity
```

**2. It then re-targets to the wrong entity.** The card leaves from under the
pointer, `mouseleave` fires, the pointer lands on a neighbouring row, and the
card reopens collapsed for that row. Reproduced twice: VM-515→VM-601,
VM-503→VM-511. Same class as the Fokus-button bug the code comments record
("gemessen: B-213 statt B-307"); the 90ms `uebernahme` guard cannot catch it,
because a card removing itself is not a row crossing.

**3. The payload cannot be read.** Expanded: 868px on a 900px viewport (96%),
holding 1514px of content in an 866px box — 43% below its own fold, scrollable
only while a pointer is held inside, destroyed 260ms after it leaves.

**4. Pointer-only and unpinnable.** Keyboard focus on a row opens the card with
`#k-mehr` **hidden** — there is no keyboard path to the profile at all. Click
pins `#panel` but not `#karte`: the shallow surface is pinnable, the deep one
is not.

**Why the suite is green.** All five card tests in
`tools/tests/test_struktur_ui.py` hover `#B-307` near the top of the tree, and
Playwright scrolls it into view first — so they run at low `scrollY`, where
document-y 8 and viewport-y 8 nearly coincide and the mix-up is invisible.

Full trace: `/opt/999-Agentic-Engineering-Framework/docs/reports/T-3447-struktur-double-hover.md`

## Root cause — fix this, not the symptoms

**Hover is being used to deliver a document.** The profile has headed sections
(*Was sie tut*, *Zuständigkeit*, *Verantwortung*), dated sources and a dissent
note. Hover answers *which row is this?* It is the wrong instrument for *what did
we find out about it?*, because it cannot be held, linked, printed or reached
without a pointer. The second hover stage exists only because one hover surface
could not carry an article.

Do not fix this by tuning delays, sizes or z-index. All four defects share one
cause and go away together when the cause does.

## What to build — one gesture per question

**Point to identify. Click to read.** Two surfaces, not three.

**1. Delete `#karte` as a hover product.** The sticky `#panel` becomes the only
hover response. Keep its fixed height and its no-reflow property — the code
comments show that was hard won, and nothing here may reintroduce tree movement
on hover. Add to it the one line the collapsed card owned: whether a researched
profile exists and whether findings hang at this entity.

**2. Click opens a persistent detail pane.** Not a tooltip. It must:

- stay until explicitly dismissed (Esc, a close control, or clicking another row)
- scroll normally, with the page, at a width that suits prose — not 416px
- take keyboard focus, and be fully reachable by keyboard alone
- be addressable by the `#fokus=<id>` hash convention the page already uses
- print
- carry the profile, sources, dissent and recorded refusals

On viewports under 900px it becomes a bottom sheet. Above that it is the
right-hand rail.

## Design language — already published, follow it

The layout and the row anatomy are specified in the project's design system,
component `StructureTree`, with `ProvenancePanel` for the rail:
https://claude.ai/artifact/KHsqdBoUerfTPVC8Ds74ZE

The tokens are already in the built page's `:root`. Use them; do not introduce
new colours.

- Two panes: tree `1fr`, rail `360px`, gutter `--space-6`, page max `1320px`
- Rail ground `--paper-2` on a `--rule` hairline; `position: sticky`
- Under 900px the rail becomes a sheet carrying `--shadow-panel` — the only
  place a data surface may have depth
- Path hops `--ink-soft` with `--evidence-strong` arrows
- **Colour means evidence strength and nothing else.** `--selected` marks the
  open row: that is position, never status
- `(zu prüfen)` keeps `--claim-unconfirmed` plus its hatch, and attaches to the
  **type**, not the row

## Constraints

## The regression test that must exist

The current suite cannot see this bug. Add to
`tools/tests/test_struktur_ui.py` (harness: `expand(page)`, viewport 1280×900,
run with `python3 -m pytest tools/tests/test_struktur_ui.py -q`) at least:

1. **At a scrolled position** (`window.scrollTo(0, 3000)`, not the top of the
   page): open an entity's detail, then assert the surface still names the
   entity that was chosen. This is the test that would have caught it.
2. The detail surface **survives the pointer leaving** — move the pointer far
   away, assert it is still open and still the same entity.
3. **Keyboard alone** reaches the researched profile: focus a row, activate by
   keyboard, assert the profile is visible and focusable.
4. The detail surface **never exceeds the viewport** and its content is
   reachable by ordinary page scrolling.
5. Hovering a row **does not move the tree** — the existing
   `test_hovering_does_not_move_the_tree` must stay green.

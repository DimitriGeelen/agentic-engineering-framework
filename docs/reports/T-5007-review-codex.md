1. **The cleaning boundary is incomplete on both routes.** `lib/issues.py:_scrub` removes selected host/IP patterns and the executing machine’s hostname; it does not cover arbitrary peer hostnames, paths, accounts or secrets. `cmd_comment` does not universally scrub outgoing text. Example: a relay posts `/home/alice/customer-x` or a token embedded in a reproduction command; a bot bypasses the wrapper using `gh`. **Fix:** require one publication gateway for titles, bodies, comments, verdicts and attachments. Check Unix/Windows paths, IPv4/IPv6, DNS names, usernames/emails, credential-bearing URLs, token formats and known private identifiers. Use structured, allowlisted public fields and approved project aliases. Unknown secrets, encoded content, screenshots and contextual identification cannot be reliably caught automatically; ambiguous material needs review. Keep raw evidence private, including outside mirrored report files.

2. **The default relay route bypasses the intake behavior the design assumes.** In `lib/issues.py:cmd_sync`, issues authored by the repository owner receive ledger-only internal classification, no intake comments or labels, and their replies are skipped. Also, `cmd_sync` itself does not create tasks. Example: AEF files a peer bug under the operator’s account, but no normal acceptance/task workflow follows automatically. **Fix:** explicitly define task creation/linking and introduce authenticated peer provenance independent of issue authorship. Store a private mapping between GitHub actor, source project, request ID and destination. Never trust a body saying “source: project-X” as authentication or treat peer identity as approval authority.

3. **The promised FAILS/reopen loop does not exist.** Sync reads open issues and only the issue author’s comments; `not-fixed` becomes a decision item, not a reopen. Release handling holds FAILS but does not reopen closed issues. Stage deduplication uses `(issue, stage)`, so a second fix cycle can suppress fresh updates. Moreover, closure is not exclusively submitter-confirmed: release evidence can close an issue, and unanswered confirmation requests expire after 14 days. Example: a peer reports FAILS privately after automatic closure and nothing changes publicly. **Fix:** extend the existing lifecycle with authenticated, version-specific verdict events, retryable sidecar notifications, private evidence references, sanitized public summaries, explicit reopen/task handling and cycle-aware idempotency. Define how pending peer tests affect closure.

4. **Per-project accounts have unresolved terms and credential risks.** GitHub requires human-created machine accounts with a responsible owner and permits only one free machine account in addition to a free personal account. One operator creating free accounts for every project conflicts with that limit. [GitHub Terms, B.3](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#3-account-requirements). Example: several hosts share the operator’s broad token; compromising one exposes all its privileges. **Fix:** settle compliant ownership/account arrangements or evaluate a GitHub App. Use minimum repository/issue permissions, separately revocable host credentials, expiration and rotation, secure local storage, and an offboarding inventory. A committed registry should contain credential references, never tokens. Peer bots still need the identity mapping in finding 2.

5. **The relay is a single point of failure and discretionary bottleneck.** “Can always report to AEF” does not guarantee eventual publication when AEF is down, backlogged or disagrees. Example: a request remains privately queued indefinitely while the sender assumes it was filed; retrying through a bot creates another issue. **Fix:** separate durable receipt, publication and acceptance. Provide stable request IDs, acknowledgements containing the issue URL, retry/reconciliation, queue-age alerts, an alternate worker or escalation route, and explicit rejected/deferred reasons. Routine publication should follow policy; disagreement about implementation should not silently erase the request.

6. **Duplicates lose the identities needed for verification.** Pickup deduplication includes source project; issue classification supplies only title-similarity hints. Neither establishes a canonical problem with multiple reporting projects. Example: two peers and an outside contributor report one defect; three tasks appear, or consolidation leaves only the original author eligible to confirm. **Fix:** distinguish transport retry IDs from semantic duplicate detection. Maintain canonical issue/task links and all affected reporters privately, preserve their separate verdicts, notify every subscribed project, and define how conflicting results prevent premature closure.

7. **There is no executable migration contract.** `bin/fw` still routes `pickup` and `issues` separately. Existing issue forms request raw `fw doctor` output, logs and screenshots, without a safe peer-report schema. Example: replaying 82 processed envelopes creates duplicate tasks and publishes historical host details; removing pickup breaks old agents and deferred work. **Fix:** inventory the 82 processed, 10 rejected and 4 auto-deferred pickups; map existing tasks and migrate only unresolved, sanitized requests. Initially wrap structural `fw pickup` submissions, preserving status/history and private traffic. Specify cutover, old-client compatibility, rollback, source/type labels, template fields and the private security-report route.

8. **“Fixed” must remain tied to the authoritative source.** T-5006 documents GitHub merges lost through mirror replacement. Example: a linked PR closes an issue although its fix never reaches the private source. **Fix:** coordinate PR ingestion with T-5006, prevent premature automatic closure, and notify peers only for source-integrated commits available on the public mirror/tag.

Overall verdict: **sound with fixes** — the channel split is reasonable, but publication safety, identity, lifecycle recovery and migration require concrete implementation before rollout.

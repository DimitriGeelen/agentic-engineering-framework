1. **High — PID isolation does not prevent host service control.** `termlink.sh:1660` isolates PIDs and mounts a new `/proc`, but retains host credentials and filesystem access, including service-control sockets. This environment exposes `/run/systemd/private`, `/run/dbus/system_bus_socket`, and `/run/user/0/bus`. Where credentials authorize it, a seat can ask the host manager to stop services without signalling their PIDs directly. The antigravity `sudo -u` remains inside the namespace but does not eliminate service permissions belonging to that account. **Fix:** restrict host control sockets and privileges, or use a dedicated account with no service-control authority.

2. **High — refusal restores the original vulnerability without an enforcing guard.** `_fw_seat_pidns` logs refusal and continues unisolated; `judge_cli.py:779` adds instructions, not command enforcement. The task’s command-guard criterion remains unmet, and attempted violations are not audited. Ordinary unprivileged launches can therefore retain the original `pkill` failure mode. **Fix:** fail closed or provide the promised isolated-user fallback; implement and test command refusal and attempt logging. `FW_SEAT_PIDNS=off` is logged, so it is not intrinsically silent. Normal runtime environment scrubbing removes it, and the signed review environment excludes it; however, callers supplying `_FW_RUNTIME_ENV_CLEAN=1` bypass that scrub, as the tests do.

3. **Medium — tests substantially underprove isolation and cleanup.** `t5008_seat_process_isolation_test.py` exercises only an opencode stub. The decoy test never starts a matching process *inside* the seat, so it proves non-discovery, not successful selective cleanup. Codex and antigravity coverage checks source strings only. There are no guessed-PID, parent-signalling, ptrace, service-control, or real refusal-path tests. Both namespace integration tests skip when `unshare` fails—which it does here. The watchdog test checks one child’s command-line disappearance, not worker, wrapper, detached descendants, or zombies. **Fix:** require these integration cases on a namespace-capable runner, including the real sudo transition and TERM-resistant descendants.

4. **Medium — timeout recording has a race.** `_fw_watchdog`, `termlink.sh:1636–1641`, signals the namespace child before creating `timed_out`. If that child handles TERM and exits quickly, `unshare` can exit before the subsequent `kill`, causing an early return without recording timeout. The main runtime can also reap the wrapper and terminate the watchdog in that interval. **Fix:** record timeout before signalling. The final SIGKILL plus `--kill-child` is plausible cleanup for the ordinary namespace path, but the tests do not establish the stronger “every child, no orphan” claim across all launch paths.

5. **Medium — isolation metadata is advisory, not verified evidence.** `_fw_seat_pidns` records “own PID namespace” before the actual launch succeeds; `FW_SEAT_PIDNS=on` skips probing entirely. Metadata writes are best-effort and the field is not incorporated into signed isolation evidence. **Fix:** distinguish requested/probed/established isolation and authenticate the established result. The signing parent remains outside the namespace, so I found no inherent parent-check regression.

# Independent review — T-4965 scoped access grants

**1. The fence is path-shaped; the share is reachable by paths the draft never names (most severe).** `never_write` fences `/mnt/nas-admin`, not the share. Typed, today, no script needed: `mkdir /tmp/nas && mount -t cifs //nas/Projects /tmp/nas -o credentials=/root/.smbcreds` — `mount` is in no write-verb list in `lib/shell_write_scan.py` (`_ALL_OPERANDS`, `COPY_FAMILY`, etc.), and `/tmp` is an allowed zone in every pass of `check-project-boundary.sh`, so every later write to `/tmp/nas/…` is admitted. Likewise `smbclient //nas/share -c 'put …'` and (sshfs today) `ssh admin@nas 'rm …'` touch no filesystem path: `//nas/share` fails Pattern 4's `KNOWN_TOPS` heuristic (`top` is empty), so they pass. Fix: add `mount`/`umount`/`fusermount` to the scanner's write verbs; block typed network clients to the NAS host (name `smbclient`/`ssh` in the scope limits); doctor must reconcile `/proc/mounts` against the grant `via` list and alarm on any other mount of the same source.

**2. The ledger and audit log are unguarded, typed-editable — a standing delete key.** They live inside the project, so the boundary hook allows Write/Edit on them; `shell_write_scan.py` guards only `human-ac-ticks.jsonl`/`standing-delegations.jsonl`/`.tasks`. Since §4a step 1 and §4b let `fw grants delete` run *because the ledger says so*, a typed `Edit` appending `{"path":"/mnt/nas-admin/rpt.docx","temp":true}` yields deletion of an operator file with no approval (certainly under §4c b, and under (a) too if the executor trusts our runtime's ledger claim). Fix: add `created.jsonl`/`audit.jsonl` to the guarded set (T-3695 leg); the delete authority must be the NAS-side owner, never the local ledger.

**3. Ledger soundness: existence-based confirm, path-as-typed keys.** (a) PostToolUse "confirms the lines whose paths now exist": the operator works on a live share — if he creates at a pending path in the pre→post window, his file is confirmed agent-owned; parallel tool calls confirm each other's stale lines. Bind pending lines to `tool_use_id` (tier0 round 4 does exactly this) and confirm by NAS owner or content hash, not existence. (b) §3 "keys on the path as typed": `/mnt/…/g/new.txt` vs `cd /mnt/…/g && echo >> new.txt` vs SMB case-folding miss each other (fail-closed noise at best). Key on the resolved path; casefold on cifs. (c) Deleted-then-recreated: operator deletes the agent's `x.txt` (unseen by the ledger) and creates his own at that path — the live entry lets the agent modify *his* file. Close entries whenever the path is observed missing; re-verify ownership at every grant decision.

**4. Extractors and script-created files bypass the ledger entirely.** `tar`/`unzip`/`7z` are in `EXTRACTORS`, but boundary mode explicitly skips them (`if extracting and not ctx.boundary`, shell_write_scan.py:1427); §2's classification never names them. `tar -xf proj.tgz -C /mnt/pen-create/g` creates members the ledger never saw (so they can never be modified or deleted — §4a refuses non-ledger paths even with the operator's approval, inverting who is authoritative), and a member `../../opfile` escapes the grant while the typed operand stays inside. Fix: refuse extractors under grants until member enumeration exists; stage into the project and copy; let a Tier 0 override delete non-ledger paths.

**5. Hard links convert operator files into "agent-created".** `ln /mnt/pen-create/g/opfile /mnt/pen-create/grant/mycopy` — same mount, succeeds; `ln` destination is classified create, source "is not a write" (`_boundary_segment`), the ledger records `mycopy`, and on ledger-only mounts (the "general pattern") `sed -i mycopy` rewrites the operator's inode. CREATOR OWNER blocks the modify on 050's mounts but not the false ledger entry. Fix: classify `ln` sources; refuse hard links unless the source is ledger-owned.

**6. §4c — claim correct; executor spec incomplete.** Right that no local secret resists root (it can also just watch the local process use it — so the runtime must not be local, confirming (a)). The executor must check, itself: the operator's approval over its own channel; NAS-side ownership of the exact path (our ledger is root-writable, so it proves nothing); re-verify at execution time (approve delete of A, then rename an operator file onto A — TOCTOU); resolve symlinks server-side; a single-use, nonce-bound request. The temp route's "ledger check stands in for the operator's approval" is unsound on ledger-only mounts — restrict it to mounts with NAS-side ownership or drop it.

**7. Grant-file guard gaps.** The audit fires only on *commits*; a script (or an untyped edit left uncommitted) changes the working tree, which is what the hook reads — silent widening. `git checkout/restore/stash/apply -- policy/access-grants.yaml` is a write the draft doesn't name. And `fw config set BOUNDARY_EXTRA_READ_PATHS` (T-4751) remains agent-typeable self-service read widening, contradicting "the agent can never edit its own grants". Fix: digest check (operator-signed or HEAD) at every fire; extend the guarded verb set; migrate read grants into the operator-owned file.

**8. Slices.** Missing: ask 2's steering/`never_write` enforcement is in no slice (test 8 rides slice 3 but the roots come from slice 2's file); the audit log (§5) is in no slice; mount hygiene (finding 1) must precede the create level. Steering should refuse-and-message, never silently rewrite paths.

**Verdict: sound with fixes.** The layering (NAS-side accounts, off-host executor, fail-closed ledger) is right, but as drafted the delete route is unsound (findings 2, 3, 6) and the mount/network surface (finding 1) is outside the fence the design relies on.

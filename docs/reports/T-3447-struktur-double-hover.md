# The double hover on Die Verwaltungsstruktur

Investigation of the two-stage hover disclosure on `struktur.html`
(`http://192.168.10.107:8140/struktur.html`).

Target project: `/opt/1409-sprind`. The markup, CSS and JS are generated by
`tools/site_build.py`; the page under test is `site/struktur.html`.

## What the operator reported

> "There is a double hover. If you go to the entities there comes a small box,
> and if you go to the small box there comes a large box. I feel there is a
> better way to present that."

Confirmed, and it is worse than a redundant gesture: the second stage is
unreliable, and when it does work the thing it reveals cannot be read.

## What is actually on screen

Three disclosure surfaces describe one entity. Measured at 1440×900:

| Surface | Trigger | Size | Carries | Can it be kept open? |
|---|---|---|---|---|
| `#panel` (sticky, top) | row hover | 178px, fixed height | path, name, meta, 2-line description, Fokus button | **yes** — click pins it |
| `#karte` collapsed | row hover + 90ms | 416 × 165 | name, meta, description, relation to the run, Fokus button, hint | no |
| `#karte` expanded | hover the card itself | 416 × **868** | **path again**, researched profile, sources, dissent / refusal | no |

Name, meta and description appear on all three. The path appears twice.
`Nur diesen Zweig zeigen` appears twice. The only content unique to the
collapsed card is one line — the relation to the run
(*"Kein Befund dieses Laufs hängt an dieser Stelle."*).

So the first box is very nearly a copy of a panel that is already filled and
already visible.

## Defect 1 — entering the card teleports it

`letzteZeile` is initialised to `0` and **never assigned**. `imSchirmHalten`
takes an optional row position, but the only call site passes nothing:

```
site_build.py:1757   var letzteZeile = 0;
site_build.py:1758   function imSchirmHalten(zeileOben) {
site_build.py:1759     if (typeof zeileOben === 'number') letzteZeile = zeileOben;
site_build.py:1761     var t = Math.min(Math.max(8, letzteZeile - 8),
                                        clientHeight - h - 8);
site_build.py:1763     karte.style.top = Math.max(8, t) + 'px';
site_build.py:1776     imSchirmHalten();        // ← no argument, ever
```

So `t` collapses to `8`, and `8px` is written to an element positioned
`absolute` — i.e. in **document** coordinates, while `clientHeight` is a
**viewport** measure. The two coordinate spaces are mixed.

Traced with a MutationObserver on `#karte`, viewport 1440×900, `scrollY` 3000:

```
tree.mouseover VM-515
   top: 3346.7px   h: 165   k-mehr hidden      ← opens beside the row
card.mouseenter
   top: 8px        h: 868   k-mehr shown       ← expands AND jumps ~3.3k px up
card.mouseleave ×3
tree.mouseover VM-601
   top: 3376.45px  h: 185   k-mehr hidden      ← reopens for a DIFFERENT entity
```

## Defect 2 — which then re-targets to the wrong entity

Because the card leaves from under the pointer, `mouseleave` fires, the pointer
lands on a neighbouring row, and the card reopens — collapsed — for that row.
The reader aims at one entity's profile and is handed another's summary, with
no indication anything went wrong.

Reproduced twice, independently:

| Hovered | Card ended up showing | `k-mehr` |
|---|---|---|
| VM-515 | VM-601 | hidden |
| VM-503 | VM-511 | hidden |

This is the same failure class the code's own comment records having fixed for
the Fokus button (*"gemessen: B-213 statt B-307"*). The 90ms `uebernahme` guard
cannot catch it, because a card removing itself from under the pointer is not a
row crossing.

## Defect 3 — the payload cannot be read even when it works

With the card correctly placed, the expanded state is **868px tall on a 900px
viewport — 96%** — and holds **1514px of content in an 866px box**. 43% of the
profile sits below its own fold, reachable only by scrolling inside a box that
is being held open by pointer position, and destroyed 260ms after the pointer
leaves. Scroll position goes with it.

The content is not tooltip material. It is an article: headed sections
(*Was sie tut*, *Zuständigkeit*, *Verantwortung*), dated sources, and a dissent
note recording disagreement between sources.

## Defect 4 — the deep layer is pointer-only, and unpinnable

- Keyboard focus on a row opens the card with `k-mehr` **hidden**. There is no
  keyboard path to the researched profile at all. The card contains 4 tabbable
  controls that appear and vanish with pointer position.
- Click pins the **panel** (verified: VM-515 stays after the pointer moves
  away) but not the card. The shallow surface is pinnable; the deep one is not.
  That is backwards.

## Why the test suite is green

`tools/tests/test_struktur_ui.py` covers the card well — `never_covers_its_own_row`,
`opens_next_to_the_row`, `never_grows_past_the_screen`, `survives_the_pointer_
reaching_it`, `unfolds_when_entered`. Every one of them hovers `#B-307`, near the
top of the tree, and Playwright scrolls it into view first — so they all run at a
low `scrollY`, where document-y 8 and viewport-y 8 nearly coincide and the
coordinate mix-up is invisible.

The bug needs a scrolled page to appear, and nothing scrolls. A regression test
should assert, at `scrollY ≈ 3000`, that after entering the card `#k-id` still
names the row that was hovered and `#k-mehr` is still visible.

## Root cause

Hover is being used to deliver a document. Hover answers *which row is this?*
— it is the wrong instrument for *what did we find out about it?*, because it
cannot be held, linked, printed, or reached without a pointer. Every defect
above follows from trying to make it do both: the second stage exists only
because one hover surface could not carry an article, and a second hover was
cheaper to add than a real reading surface.

## Recommendation — GO, one gesture per question

**Point to identify. Click to read.** Two surfaces, not three.

1. **Delete the card as a hover product.** Keep the sticky `#panel` as the only
   hover response. It already carries path, name, meta and description at a
   fixed height that never shifts the tree — the property the code comments show
   was hard won. Add the one line the collapsed card owns: whether a researched
   profile exists and whether findings hang there.

2. **Make click open a persistent detail pane** — the right-hand rail of the
   published design language, or a bottom sheet under 900px. It stays until
   dismissed, scrolls normally, takes keyboard focus, is addressable by the
   `#fokus=<id>` hash convention the page already uses, and prints. Profile,
   sources, dissent and refusals live there, at a width that suits prose rather
   than 416px.

This removes the double hover, the teleport, the re-target and the
pointer-only trap together, because it removes their shared cause.

### Interim, if the pane is too large a change now

Three one-line changes in `site_build.py` that remove the double hover without
new layout:

1. `1776` — pass the row position: `imSchirmHalten(lr.top - 4)`, and clamp in
   the same coordinate space the element is positioned in.
2. `1710` + `1775` — open the card already expanded: drop `kMehr.hidden = true`
   and the `mouseenter` unfold. One hover, one box.
3. Let click pin the card as it pins the panel.

This is a mitigation, not the fix: the profile is still an article inside a
416px hover box, and still unreachable by keyboard.

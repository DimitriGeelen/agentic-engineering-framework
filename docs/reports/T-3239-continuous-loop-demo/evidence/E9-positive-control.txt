WHY THIS FILE EXISTS
--------------------
Four setup defects survived several full E9 runs undetected, because every step
was suffixed `>/dev/null 2>&1` and the backlog counter counted whatever happened
to be in .tasks/active/ — which, with `fw task create` silently failing, was fw
init's onboarding curriculum. The runs measured the loop against the wrong five
tasks and reported "backlog: 5 real tasks", which was true of the wrong five.

So before spending another 30 minutes of wall clock on a live run, the rig itself
is proved. The question is not "does the harness produce files" but "can a task
be closed WITHOUT doing the work?" If it can, every assertion downstream is
vacuous and a green result means nothing.

L-653: a negative result is only evidence if the positive control fires. This is
that control, run in all three directions.

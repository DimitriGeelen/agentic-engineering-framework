## 1. Diagnosis

Of the 39 §6 entries: ≈22 language (D-03…D-16, D-18, D-20…D-23, D-25, D-28) — bash evaluating data-as-code (D-06…D-09) and exit-status semantics (D-10…D-16, D-20); ≈5 parsing (D-27, D-31, D-33, D-37, half of D-32) — hand-written matching vs shell expansion; ≈12 spec (D-17, D-19, D-24, D-26, D-29, D-30, D-34…D-36, D-38, D-39, halves of D-01/02/05) — fail-open choices and isolation. So ~55% language, ~30% spec, ~15% parsing.

But §5 is the mirror image: of 18 open/residual cases, zero are language-caused. Nine are expansion-miss parsing (T0-061, 063–070; D-37), six serialisation/environment spec (T0-059/060/062/072/073; D-38), three isolation spec (T0-015/016/029; D-39). The two defect populations barely overlap. A language rewrite fixes the silent-allow class; it would not have closed any open §5 case. The §5 class demands an architecture change (where enforcement sits), the §6 class a language change (how the guardrail is written). D1 must do the first or D2 is irrelevant.

## 2. Security contract per layer

**Guardrail layer** (hooks/adapters + Go engine; files root-owned, agent-read-only). Trusted: the harness runs hooks and honours exit 2 (§2.1 — contractual, not enforced); root ownership once D5 lands. Guarantees to (a): the parser+allow-grammar closes the spelling class for text it sees; unmapped/unparseable → deny (R5 direction, §5 pattern). Against (b): nothing alone — the agent can exec `/usr/bin/git`, run scripts uninspected (§3), use ungated tools (§2.2), or wait out a timeout (§2.1). Unsupported input is denied, not guessed at.

**Isolation layer** (non-root uid; root-owned hooks/settings/store/keys, §11 table inverted; managed settings `allowManagedHooksOnly`, §10.2; root-installed pre-push; OneDev server-side protection; broker). Trusted compute base: root, kernel mounts/namespaces, broker code + operator key, server config. Against (a): bounds every miss to the workspace blast radius. Against (b): approval forgery and self-approval become impossible because the key is unreachable by uid (closes T0-015/016/029, 030–038, 048, 055–071); spelled force-push dies at pre-push/server regardless of text (T0-018, 040–042, 049–052); hook tamper dies at ownership (D-39). Excluded: workspace-local destruction (accepted), script contents (§3), cage escapes (out of scope). Broker absent → elevated ops denied, never sudo-fallback.

**Gaps only the harness vendor can close:**
- hooks fail open on crash, failure-to-start, timeout (§2.1, D-35) — no fail-closed mode exists;
- ungated tools: Read, NotebookEdit, all MCP but one (§2.2) — matcher/coverage limits;
- sessions run with `--setting-sources user` skip project hooks entirely (§14);
- sandbox defaults to warn-and-run-unsandboxed; `excludedCommands` has no managed lockdown (§10.3);
- Bash rules "aren't a security boundary" around invoked programs (§10.1, vendor's own words);
- harness-internal truthfulness (does it execute only wire-carried `tool_use`?) is a black box (§13.1).

## 4. D1–D5 reasoning

**D1.** Hooks are S1 — "never a boundary" (§13.1) and other harnesses run none (P-063, §14). So the boundary moves to effects: non-root agent, root-owned enforcement (§11), root-installed pre-push, server-side ref protection, broker-held approvals. *Closed* under §3(b): forgery/self-approval (T0-015/016/029, 063–071), tamper (D-39), env redirection (T0-001, 006–009, 021–027, 039), spelled force-push (T0-018, 040–042), cross-remote reuse (T0-072). *Remains*: workspace-local destruction (blast radius, guardrail-only), script contents (§3), vendor gaps (§2), cage escapes. The proxy is phase 2 — it adds harness-independent intent governance for opencode/codex — after its substring matcher (§13.1 Q3) is replaced by the D2 engine.

**D2.** Go wins on evidence, not taste: mvdan's `expand` is the only maintained expansion engine among the §9 parsers, i.e. exactly D-37; static binaries satisfy no-toolchain/offline (§7.4); direct invocation removes the measured dispatcher cost (§4). Partial disagreement with T-586: TS stays right for `fw-util` and adapters (the P-063 bridge is TS), wrong for the matching engine (no parser); its "TS replaces Python" premise (Node guaranteed) holds only for Claude Code hosts. Partial agreement with T-2428: architecture yes, but the relay's substring patterns are the §5 defect class reborn and must call the engine.

**D3.** Criterion kept, one clause added: "if this fails silently, can an unreviewed destructive action run?" Core: Tier 0 engine + pre-push/interposition; task/focus safe-command engine (G-077 is the same parsing defect, D-31); the `hook` dispatch arm's fail-semantics (§2.3 — T-1360's allow must invert for the engine); govd holder/broker/policy-emit (§13.1); ledger signature verification once keys move behind the broker. Excluded: task-close workflow gates (spec churns), budget/checkpoint (fail-open by design, §2.3), the other ~100 subcommands, Watchtower.

**D4.** Cross-compile in CI for linux/amd64+arm64 and darwin/amd64+arm64; WSL uses linux binaries; native Windows stays unsupported (§7.3). Vendored via the existing rsync `do_vendor()` (§7.1) with a release-signed SHA-256 manifest; `fw upgrade` verifies before swapping the version pin. Runtime: hash check, then exec. Missing, mismatched, or failing to start → hook exits 2 with a repair instruction; a human runs `fw repair` outside the session. Old consumers keep working: text modules unchanged, binaries additive, rollback = previous release retained by the pin.

**D5.** Broker — the T-2428 holder/envelope, already built (§13.1) — runs as root under a service uid, unix-socket only, append-only audit, one-use TTL grants bound to structured action keys (structured serialisation fixes T0-059/060; nonce fixes T0-029). One-tap: Watchtower/ntfy already exist (§12.1); the tap's authenticity becomes real because the signing key sits outside the agent's uid (killing T0-071's stakes). Sudoers only for the emit/install split; polkit rejected (not on macOS/WSL); harness prompts rejected (harness-dependent — P-063). Tier mapping: T3 → sandbox default, no broker; T1 → in-cage guardrail; T2 → broker prompt-free categories; T0 → broker one-tap. Broker down → deny.

## 5. Migration and validation

Sequence, one module per release (§7.4 IW-5): (1) create agent uid; chown/chmod the §11 table root-only; deploy managed settings with `allowManagedHooksOnly`; enable OneDev branch/tag protection. (2) Deploy `aef-govd` (T-2430 code exists); relocate approvals/focus/bypass log; root-install pre-push (emit/install split, T-2432). (3) Ship the Go engine behind the existing hooks as a direct binary call; parity first. (4) Fold G-077's allowlist into the engine. (5) Point the relay's decide-path at the engine, then Lock-1 Part 1. (6) P-063 adapter pack from one manifest.

Validation: all 98 §5 cases become golden fixtures (blocked runs only, avoiding store writes); bats black-box suites run unchanged against the engine (§1.3); differential property tests — random commands, engine's expansion vs bash's own — plus mutation testing so the tests stay alive (L-651/L-636); chaos runs: SIGKILL broker, corrupt binary, hash mismatch — each must produce exit 2, never allow. What the suites do NOT cover: script contents at run time (§3), MCP and ungated tools (§2.2), harness internals (§13.1), live-session wall-clock (§4 caveat). Rollback triggers: any T0-101…122 regression; parity divergence beyond the known-open list; confirmed p95 budget missed; any fuzz-found silent allow; any §11 path written by the agent uid.

## 6. Strongest case against my verdict

The team is one operator plus agents with zero Go (§8): an AI-written security engine in an unfamiliar language, maintained by the same review pipeline that needed seven rounds on a regex-classifier — the polyglot verdict assumes the bats contract plus differential testing substitutes for human review of a new stack, which is exactly what T-3581 says cannot be done for provenance. T-2428 has been "in progress" and undeployed for 3.5 months (§13.1); my plan stacks five more phases on an unproven base while the text gate remains the only live barrier. The cheap legs could equally precede any engine work; if OneDev protection is absent (§11, unknown), the git boundary rests on a pre-push hook the operator could disable. And "closed" against (b) quietly excludes the workspace itself, where most real damage (T-2742's sibling) actually happened.

## 7. Assumptions and missing facts (ranked)

- OneDev server-side branch/tag protection exists and can be required — unknown (§11); if impossible, D1's git boundary weakens to pre-push only.
- p95 < 100 ms is confirmed as budget — PROPOSED only (§4); if relaxable, D2 weighting shifts toward strict Python.
- No-toolchain/offline constraints confirmed (§7.4); if a toolchain were allowed, source-distribution options reopen.
- bashlex GPL-3 is licence-blocking for Apache-2 distribution (§9) — needs legal confirmation; if cleared, Python-strict gains.
- Passwordless sudo (`sudo -n`, §11) is removed when the agent uid is demoted; otherwise sudoers-based escalation reopens (b).
- Watchtower/CSRF surface (T0-071) is moved out of agent reach with the broker; until then `--from-watchtower` paths are agent-reachable.
- Sub-agent distinct principals (§13.1 residual) is solvable without harness changes; if not, attribution degrades for in-process sub-agents.
- The proxy's non-Anthropic wire formats are "isomorphic" (§13.1 Q5, unverified).

## 2. Four findings, measured

Each was read out of the source or the live state files this session — not inferred.

### F1 — Nothing takes the next turn (this is the "general menu")

All 28 registered hooks in `.claude/settings.json` were enumerated. There is **no `Stop`
hook, no `UserPromptSubmit` hook, and no `SessionEnd` hook.**

The restart chain is: budget critical → `checkpoint.sh` / `budget-gate.sh` writes
`.context/working/.restart-requested` → claude exits → `bin/claude-fw` sees a fresh signal →
`sleep 3` → `claude -c`.

That reopens the session **and then waits for a human to type.** `FW_NEXT_DIRECTIVE` is
exported and surfaced by the SessionStart hook as `additionalContext`, but additional
context does not cause a turn — it is wallpaper on an empty prompt.

> The loop has no driver. This is not a compaction failure.

### F2 — `claude -c` restores the context, it does not free it

`bin/claude-fw:338` sets `CLAUDE_ARGS=("-c")`. `-c` continues the *same* conversation — the
one that just hit critical. `post-compact-resume.sh` resets the budget **gauge** to
`{"level":"ok","tokens":0}`, which is right for a genuinely compacted session and wrong for
this one: the needle moves, the tank does not.

So the resumed session re-crosses critical within a few tool calls, writes another signal,
restarts again — until `MAX_RESTARTS=5` (`bin/claude-fw:209`) gives up. That is the
"*keep* getting kicked out": it repeats by construction rather than happening once.

**The exit-and-`-c` path can never free context.** This is the strongest technical support
for the operator's instinct to compact *in-session* instead.

### F3 — Continuous mode reports enabled while structurally terminated

`.context/working/.continuous-mode.yaml`:

```yaml
enabled: true
last_terminated_reason: expires_at 2026-06-17T00:00:00Z passed (now 2026-08-26T11:20:05Z)
```

Expired **70 days ago**. `inject-next-directive.py` refuses with `LOOP TERMINATED` when caps
are hit, while the file's first line reads `enabled: true`. Same false-green family as
`fw designer`'s `PRESENT ✓` in T-3157: a true statement about one thing, read as a statement
about another.

### F4 — The restart sentinel is only consumed on one branch

`post-compact-resume.sh:42-48` removes `.auto-restart-pending` **only** when
`SOURCE_TAG = startup`. This session returned via `/compact` (source `compact`), so the
sentinel written at 13:13 is still on disk. The next *genuine cold start* will be misread as
a loop continuation. Latent; no instance observed.

## 3. The operator's fork, checked against the code

Their caveat about `/clear` is not a precaution — it is the literal current state.

| | fires on `/compact` | fires on `/clear` |
|---|---|---|
| `PreCompact` (our handover generator) | **yes** | **no** — no `PreClear` event exists |
| `SessionStart` re-injection | **yes** (`matcher=compact`) | **no** — we register `compact`, `resume`, `startup` only |

And `agents/context/post-compact-resume.sh:28` clamps the source:

```python
print(src if src in ('startup', 'resume', 'compact') else 'resume')
```

`clear` is not in the allowlist. **So `/clear` today gives zero hooks on both ends** — no
handover written going out, no context injected coming back. If we take that route the
handover must carry the entire load, generated by us rather than by a hook, exactly as the
operator said.

**Assessment.** `/clear` is the stronger of the two: a model-written `/compact` summary is
lossy and non-deterministic, while a handover we generate is a file we control and can
verify. But it is *necessary and not sufficient* — F1 means neither route produces
continuity on its own.

## 4. Why model it in the Workflow Designer

The conformance rail (`tools/conformance-registry.yaml`, T-2621/T-2652) is
**registry-driven, not hard-wired** to the five existing maps: a map opts in by adding an
entry keyed on a `primitive`. Two primitives are implemented, one is not.

| Primitive | Fits? |
|---|---|
| `vocabulary-set` — a gateway's branch labels vs an enforced enum in code | **yes, well** |
| `transition-table` — state carriers vs a `transitions:` list | yes, with an authored state list |
| `gate-referent` — cited enforcement points must resolve to live code | **not implemented** |

Three gateways in this machine have real enums behind them:

| Gateway | Map branches | Enforced by |
|---|---|---|
| budget level | `ok / warn / urgent / critical` | `budget-gate.sh` 75/85/95 ladder |
| **SessionStart source** | `startup / resume / compact` | `post-compact-resume.sh:28` allowlist |
| restart signal | `fresh / stale / max-restarts` | `bin/claude-fw:293-345` |

The middle one earns its keep. **If the map draws the `/clear` route it asserts a `clear`
branch, and the rail goes RED immediately** — the code's allowlist has no `clear`. The
missing support stops being prose in this document and becomes a divergence the daily audit
reports until someone closes it or corrects the map. (Whether a deliberately-red entry is a
legitimate use of the rail is IW-3 — T-2619's cascading-detail model assumes entries go
green.)

**Honest limit.** F1 is an *absence*. A map can draw the missing edge; no implemented
primitive can assert "a hook that should exist doesn't." `gate-referent` is exactly that
primitive and it is not built. So the map would enforce the three enum gateways and
*display* the missing driver — not enforce it.

## 5. What this does not claim

- That `/clear` is safe today. It is not — both hook ends are missing.
- That the map fixes anything by itself. It specifies and it detects; it does not drive.
- That F4 has caused a real misfire. Latent, unobserved.
- That fixing F1 is small. A `Stop`-hook driver decides when the loop *stops*, which is a
  safety question rather than plumbing (IW-2). That is why this is an inception.

## 6. Recommendation

**GO.** Not DEFER: the evidence is complete — four defects located in source, and the
operator's own proposal checked against the allowlist that would have to change. What
remains is a fork the operator owns, not a knowledge gap.

Proposed shape, for the operator to rule on:

1. **Driver (F1)** — a `Stop` hook that re-injects the next directive as an actual turn,
   bounded by the existing `max_iterations` / `expires_at` caps. Without this, nothing else
   matters. Termination authority is IW-2.
2. **Boundary crossing (F2 + §3)** — own both ends of `/clear`: generate the handover
   ourselves (not via `PreCompact`, which will not fire), register a `clear` SessionStart
   matcher, and widen the `post-compact-resume.sh:28` allowlist. IW-1 / IW-4.
3. **Honesty (F3, F4)** — `enabled:` must reflect terminated state; consume the sentinel on
   every branch.
4. **Specification (§4)** — author the map, add a `vocabulary-set` registry entry on the
   SessionStart-source gateway. IW-3 decides whether it lands deliberately red.

Legs 1 and 2 are the fork the operator decides. Legs 3 and 4 are mechanical either way.

## 9. Correction to §3 — `/clear` IS ownable on the way out

§3 concluded "`/clear` today gives zero hooks on both ends". The *"today"* is true —
`.claude/settings.json` registers only `PreCompact`, `SessionStart`, `PreToolUse`,
`PostToolUse`. The implied *availability* claim is wrong:

- **`SessionEnd` supports `matcher: "clear"`** — it fires on `/clear` specifically, and
  also on process exit / SIGTERM. We register no `SessionEnd` hook at all.
- Constraint: `SessionEnd` hooks share a **1.5 s** default timeout budget (raisable to
  ~60 s per-hook). Our handover agent takes far longer than 1.5 s, so a full
  `fw handover` cannot simply be hung off `SessionEnd` — it would have to be
  pre-staged, or spawned detached.
- There is still no `PreClear`, and `SessionStart`'s source allowlist is a separate
  question (`post-compact-resume.sh:28` clamps to `startup|resume|compact`).

Source: docs lookup, **not verified against this runtime**. Cheap to falsify — register a
`SessionEnd` hook that touches a file, run `/clear`, look for the file.

So the architecture question is **not** "what do we build". Every component ships:

The question is **which of the built things cannot work, and why that was invisible for
ten weeks.**

## 11. Three reasons it never fired — each measured, not hypothesised

**R1 — the signal is written into a void when the wrapper is absent (T-2499).**
`.restart-requested` is consumed *only* by `bin/claude-fw`. Sessions launched as plain
`claude` write the signal and nothing reads it. T-2499's own RCA found the proof: a
stale signal from Jun-24 sitting at 294K, and the only live `claude-fw` an idle orphan.

**R2 — the fix for the missing driver presumes the thing it is trying to cause
(T-2404).** T-2404 saw the defect exactly and said so: *"the substrate delivers the
directive into `additionalContext` but nothing fires `/resume` or `/start-work` — those
are skills, not hooks, so the agent reads injected text without auto-invoking the
governance ceremony… the loop arms but stalls waiting for human input."* The fix
shipped was to **append a sentence to the injected prose** asking the agent to invoke
`/resume`. That text is only read if a turn happens; the missing thing *is* the turn.

> A fix that presumes its own precondition. Same family as the false greens in Part I,
> one level up: not a check that cannot see its subject, but a repair that cannot reach
> the fault.

**R3 — `claude -c` restores the transcript rather than freeing it (§F2).** Confirmed
independently: `--continue` and `--resume` both reload the prior transcript. The
exit-and-restart path can never free context *by construction*, so it re-crosses
critical and repeats until `MAX_RESTARTS=5`.

R1 and R2 are independent single points of failure. R3 means that even with both fixed,
the loop would thrash rather than continue.

| `/goal <condition>` | runs until a stated condition is met; works headless | one active goal per session; idle check-in every 30 min; pauses after 3 idle check-ins |

| `--permission-mode dontAsk` / `acceptEdits` | unattended permission posture | — |

If the `Stop` hook continuation is real, **F1 is a hook registration, not a project** —
and arc-012's whole restart-based architecture is solving a problem that no longer
needs solving that way.

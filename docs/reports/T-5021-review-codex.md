1. **Direct posting defeats the claimed disclosure guarantee — R-29, R-38, C-7; A11/F1/4R.6.c.** A compromised peer holding a posting token can bypass its local cleaner. C-7 acknowledges this, but neither checking after publication nor restricting direct posts to verdicts prevents disclosure. **Fix:** require an unavoidable gate before publication, or obtain an explicit human decision narrowing the guarantee and accepting the exposure. Mark this as blocking.

2. **Pre-merge execution lacks a security boundary — R-13, R-17–R-18; A6/A7.** Reading code and using a disposable checkout do not prevent malicious code accessing credentials, other projects or host services. R-13 checks only runner labels; Q6’s question about what fork CI may access remains unanswered and is not explicitly listed as a gap. **Fix:** elicit requirements for credentials, permissions, filesystem/network isolation and destruction; prohibit peer execution until that boundary exists. Test attempted access, not checkout location.

3. **Merge authority is internally contradictory and insufficiently enforced — R-5/R-8, R-6/R-21; A4/A8.** R-8 forbids every agent-held token from pushing, while R-5 preserves session pushes. A4 forbids agent merges, not all agent pushes. Conversely, no requirement makes passing checks, completed review and tested revisions prerequisites for the operator’s merge; withholding recommendations does not stop the hurried approver. **Fix:** resolve push identities explicitly and require merge eligibility tied to the current commit, invalidated by subsequent changes.

4. **Trust-list and token tests permit unsafe implementations — R-38–R-39; 4R.6.c.** R-39’s acceptance criterion permits an unauthorized trust change merely being “flagged,” contradicting its prohibition. R-38 tests revocation but not repository scope or forbidden operations. Removing trust need not revoke an existing token. **Fix:** keep unapproved edits ineffective; bind membership removal to revocation; test cross-repository access, pushes, merges and unsupported writes. Establish whether the proposed permission boundary is achievable.

5. **A public project stamp is treated as identity without authentication — R-34/R-41/R-43; F5/4R.6.c.** Shared-account posts can claim another project’s identity; no requirement binds verdicts to an authenticated source and tested revision. A compromised peer could spoof confirmation or reopening. **Fix:** require authenticated attribution and verdict correlation, with explicit rejection tests. Section 10.7 records the gap but supplies no safe interim behavior.

6. **Opt-out requirements directly contradict mandatory identification — R-33 versus R-34/R-51; F4/F5/F8.** R-34 requires public project IDs without R-33’s exception; templates likewise require the ID. R-33’s protection is framed around relayed issues, leaving direct posts and later comments unclear. **Fix:** carry the opt-out through every public surface and retain authenticated identity privately.

7. **Further fidelity defects add or remove decisions.** R-26 adds “replies” to A10’s sidecar-only list despite authorized direct updates/comments. R-35 omits A15’s restricted visibility, private fixing and advisory publication with the fix. R-36 expands “no per-peer bots in this arc” into a framework-wide two-account limit. R-40 adds mandatory pre-commit/CI enforcement absent from §4.18.a. R-42 adds issue/task/be-tag payload requirements absent from the reproduced A12. **Fix:** restore omitted decisions, narrow overstatements and mark additions as proposals requiring answers.

8. **Important gap-review coverage is missing — §4.18.d–e, R-2/R-30–R-31.** Requirements cover AEF downtime but not GitHub downtime for PRs/direct reports, retry behavior or recoverability after account loss. Merely possessing a mirror and ledger does not demonstrate recovery. **Fix:** add loss-free outage handling and a verifiable recovery requirement, or explicitly record unanswered recovery needs.

9. **Acceptance criteria can pass while guarantees fail — §6.** R-7 permits reviewing/testing nonpilot PRs; R-6 tests intake refusal rather than preventing direct landing on `master`; R-17 tests request dispatch rather than execution; R-28 passes after changing one word while retaining secrets; R-29 passes an always-reject cleaner; R-24 checks fields but not “one screen.” R-32 excludes legitimate received/processing/private states and allows indefinite holding. **Fix:** add negative and successful cases, measurable bounds, and complete state invariants. Metadata presence alone does not satisfy meaningful testability.

10. **Drawings silently decide unresolved behavior — D-2/D-3, C-6/C-10.** D-2 places DCO in GitHub checks despite C-6, postpones checks behind the queue despite R-12, and makes WORKS a release prerequisite absent from A12. D-3 permits refusal without operator approval, contrary to A16/R-25, and unconditionally closes linked tickets despite C-10. **Fix:** reconcile drawings with requirements and visibly mark unresolved branches; the collector must not decide them through diagrams.

11. **Earlier-proposal disposition is incomplete — §8.1–8.4, §10.** Branching from `bleeding-edge` and agreeing the approach before coding lack requirements or explicit open questions/dispositions. Calling the unapproved PR template “kept, provisional” blurs proposed versus accepted requirements. **Fix:** account for every subitem and separate assumptions from verified decisions as the card requires.

**Overall verdict: red — unsound: contradictory authority and disclosure guarantees, bypassable security controls, and undocumented decisions prevent human sign-off.**

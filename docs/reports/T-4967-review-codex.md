1. **Existing scores can silently acquire a different meaning.** Sets may define different free drivers using the same ID, but `_latest_proposed_scores` discards proposal metadata (`lib/bvp.sh:651–662`). Merely recording `driver_set` does not prevent an old F1 score from becoming the new set’s F1; leaving `cmd_confirm` unchanged preserves this problem. **Fix:** preserve and check scoring provenance when reading and confirming scores. Define compatibility for reused IDs and changed scoring specs; invalidate incompatible scores while allowing pure reweighting.

2. **The promised automatic backfill does not happen.** The design says the next sweep proposes missing set-only drivers. However, the sweep explicitly skips confirmed tasks (`agents/termlink/bvp-estimator/estimator.py:3496–3497`), and delta suppression examines only confirmed keys, ignoring newly proposed drivers (`:2796–2809`). **Fix:** make missing drivers or incompatible provenance trigger re-estimation and bypass delta suppression, without overwriting confirmations. Test switching a confirmed task to a set containing an additional driver.

3. **Two scoring paths need more than the specified changes.** Auto-promote’s `max_possible` assignment is unused: actual scoring uses `weights` at `lib/bvp.sh:2102`, loaded globally at `:2070`. Making only `max_possible` per-task changes nothing. Separately, readiness returns one global weight map (`lib/arc_close_readiness.py:181`) and reuses it for individual member values (`:237–246`); updating medians alone leaves those values inconsistent. **Fix:** resolve weights at every scoring call and replace readiness’s shared-weight interface. Test promotion decisions and readiness member classifications against mixed-set CLI results.

4. **Warning-only refusal still permits invisible omissions.** A terminal warning cannot inform a `/bvp` viewer. Moreover, `collect_arcs` already swallows YAML errors (`lib/bvp.sh:264–270`), so malformed arcs can disappear before the new loader sees them. Existing arc rendering explicitly preserves otherwise empty rows to avoid precisely this invisibility (`:801–807`). **Fix:** expose refused task/arc IDs and reasons in returned data and rendered pages, preserve refused rows, and propagate collection errors. Apply this consistently to arcs, estimator sweeps, readiness and picker outputs—not just CLI rank’s amended exit status.

5. **Resolution still needs deterministic identity and parsing rules.** The proposed inherited lookup returns a filename match immediately and otherwise returns the first matching ID/slug (`agents/termlink/bvp-estimator/estimator.py:152–170`). Duplicate identities with different sets therefore select a set silently. `yaml.safe_load` also accepts duplicate mapping keys; a repeated `driver_set` is not necessarily a parse error. **Fix:** reject conflicting identities and duplicate keys, validate arc mappings, and specify how malformed files encountered during an ID scan are handled. Test missing references alongside valid tags, duplicate IDs, filename/slug conflicts, explicit `default` versus absent, and malformed YAML.

6. **The set contract does not fully protect scoring semantics.** Weight loaders overwrite repeated IDs, including free entries colliding with protected IDs (`agents/termlink/bvp-estimator/estimator.py:129–134`; `web/blueprints/bvp.py:122–127`). They also coerce weights with `int`, while the amended contract permits “numbers”; fractional weights would be silently truncated. **Fix:** require unique IDs across both sections, reject protected/free collisions, and specify finite integer weights—or deliberately support fractions throughout. Include duplicate IDs, booleans, fractions, nonfinite values and invalid scoring specifications in validation tests.

7. **The release boundary remains too early.** Publishing after slices 2+3 leaves Watchtower using its existing global weights (`web/blueprints/bvp.py:111–127`) until slice 4. That is a competing ranking surface, not merely presentation. **Fix:** ship all scoring surfaces and applicable rails under the same release tag, with mixed-corpus parity and refusal tests. Point 2’s collision rule itself is sound (`lib/arc-driver-review.sh:160–187`); point 3’s caps genuinely target scoped entries (`lib/arc.sh:1568`, `:1622–1625`). The direct-file grep revealed no additional unlisted reader, but the downstream readiness consumer above is missed.

Overall verdict: **sound with fixes** — shared set resolution is appropriate, but provenance, downstream scoring, refusal visibility and release parity remain incomplete.

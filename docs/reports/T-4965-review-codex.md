1. **Temporary-directory deletion can erase non-temporary content.** Create a temp directory, then run `mv /grant/own-permanent /grant/PEN-TMP_20261101_work/`. Neither item’s basename changes prefix, yet deleting the temp directory destroys the permanent file without approval. An operator can also place files inside it. **Fix:** enforce immutable temp status for every descendant; reject moves across temp boundaries and recursive deletes containing unauthorized objects. The executor needs trusted creation-time temp records; NAS ownership alone cannot prove temporary status.

2. **Off-host execution does not make locally supplied authority trustworthy.** Forging a local ledger row with `temp=true` could induce an unapproved remote delete. Separately, approve deletion of `/grant/a`, replace it with another object, then execute: the pathname approval now targets different data. `tier0_action.py` binds recursive deletion to pathname spelling, not object identity. **Fix:** the executor must independently authenticate approval, project, share, grant, ownership, object identity and recursive scope; enforce expiry, atomic single-use consumption and replay-safe recovery. Temp provenance must originate outside the root agent’s control. Rechecking before deletion still needs protection against replacement between check and execution.

3. **The ledger’s pending/existence protocol cannot establish authorship.** PreToolUse observes an absent path; an operator creates it before execution; the agent command fails; PostToolUse sees existence and confirms ownership. A crash leaves ambiguous pending state. Deleting and recreating a path between observations preserves a stale entitlement. A content hash or shared NAS owner does not establish which creation event occurred. **Fix:** use exclusive creation through a trusted executor and durable object-generation identifiers, transactional event recording and recovery. Never promote pending entries merely because a path exists. Apply server naming equivalence for SMB aliases; fail closed for script-created objects lacking trustworthy provenance.

4. **The scanner currently contradicts the promised unresolved-target refusal.** Read-only scanner probes showed `p=/mnt/grant/operator.txt; echo x >> "$p"` produces no checked target; `tar -xf a.tar -C /mnt/grant` and `unzip a.zip -d /mnt/grant` likewise produce none. `_check_target` rejects unresolved targets only when `ctx.mentions` holds, while boundary mode initializes it false. Relative `cd … && echo x >> operator.txt` is resolved, but the hook’s punctuation prefilter can skip bare relative commands in a grant cwd. **Fix:** integrate grant-aware cwd handling before early exits; refuse opaque mutation forms. Test the entire hook, including editors and inline commands, rather than only adding operation labels.

5. **Copy and rename need complete effects, including replacement.** `cp -r src /grant/owned-dir` can overwrite operator-owned descendants; the scanner checks only the destination operand. `mv /grant/own /grant/operator-file` satisfies the draft’s source/destination conditions but replaces an operator file. Across mounts, `mv` becomes copy plus unlink and may partially complete. **Fix:** validate every affected source, destination, descendant and overwrite; prohibit unapproved replacement and cross-filesystem moves. Restrict recursive operations to controlled execution. Define how editor atomic-save replacements and backups fit ownership and delete rules.

6. **Path validation at grant loading does not secure later path resolution.** `ln -s /mnt/nas-admin /grant/link` creates an alias after validation; a same-command write through it sees a nonexistent link during preflight. Hard-linking an operator file to a new grant pathname similarly defeats path-based authorship. Boundary-mode `_boundary_segment` explicitly skips ordinary `ln` sources. **Fix:** disallow links unless their complete effects are safely supported; bind checks to server objects and resolve operations relative to trusted directory handles without following untrusted links. Detect mount aliases and validate mount identity, not merely mountpoint presence.

7. **Guarding the grant filename misses changes to its namespace and enforcement.** `mv policy policy.old; cp -r replacement policy` replaces the grant without naming it as a write target. Git operations can replace it indirectly; changing HEAD can also defeat a HEAD-digest baseline. Editable hooks/settings can disable enforcement. **Fix:** protect ancestors, aliases, Git-mediated replacement, ledger/audit stores and enforcement configuration; authenticate the effective policy against an independently trusted operator version before use.

8. **NAS permissions and isolation must be validated before enabling create.** The draft admits the root agent retains the admin mount; running a script against that mount bypasses profile ACLs. Its local-credential warning is correct for this unrestricted host, though root confined by an externally controlled VM/security boundary need not access everything. **Fix:** isolate the agent from admin access for enforceable protection. Move NAS ACL, ownership, rename-versus-delete, descendant access, mount identity and recovery tests ahead of slice 3. Clarify create-project: the table currently permits files directly under its parent, contrary to the directory-only requirement.

**Overall verdict: unsound as drafted—delete authority, temp provenance and object identity remain unsafe, and the proposed typed-command guarantees exceed the current scanner’s coverage.**

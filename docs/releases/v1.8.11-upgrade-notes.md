# v1.8.11 — upgrade notes (draft, collected from field tests)

Behaviour changes that can turn a consumer's own tests or fixtures red after upgrading. None is a defect; adjust
the test.

1. **Tier 0 block message omits the `/approvals` URL when no Watchtower is identified** (check-tier0.sh). A test
   that asserts the URL in a sandbox without Watchtower now fails. Found by 832 (their T-1142).
2. **A build task whose `## Verification` is comment-only can no longer close** (T-4024). Fixtures with a
   comment-only Verification block need a real command (or a non-build type). Found by 832 (their T-1143).
3. **Designer node ids renumber once** (T-4224, designer 0.20.0). A map gets activity-only node ids the next time it
   is saved. Anything of yours that stores a node id (positions, current_node, overlays, corpus references) sees
   new ids after that save; 832's uid-paired table for its 24 corpus maps is `docs/reports/T-1168-node-id-map.md`
   at tag designer-v0.20.0.

## Before you commit the upgrade (until T-4232 lands)

- **Diff CLAUDE.md.** `fw upgrade` step [1/10] rewrites the framework-managed governance sections and, today,
  silently drops project-local text inside them (G-117, found by 1409: three project rules lost). Run
  `git diff CLAUDE.md` after the upgrade and restore any of your own lines before committing.
- **Check the vendored patches.** If you keep local patches under `.agentic-framework/`, list them in
  `.fwvendor-preserve.yaml` and merge upstream changes by hand (T-4233 will automate the 3-way merge).
- **Check nothing foreign is staged.** `git diff --cached --name-only -- .tasks .context/episodic` must be empty
  before your first commit after the upgrade (G-114).

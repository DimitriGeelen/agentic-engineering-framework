# v1.8.11 — upgrade notes (draft, collected from field tests)

## Behaviour changes that can turn your own tests or fixtures red

None is a defect; adjust the test.

1. **Tier 0 block message omits the `/approvals` URL when no Watchtower is identified** (check-tier0.sh). A test
   that asserts the URL in a sandbox without Watchtower now fails. Found by 832 (their T-1142).
2. **A build task whose `## Verification` is comment-only can no longer close** (T-4024). Fixtures with a
   comment-only Verification block need a real command (or a non-build type). Found by 832 (their T-1143).
3. **Designer node ids renumber once** (T-4224, designer 0.20.0; pinned now at 0.23.0). A map gets activity-only
   node ids the next time it is saved. Anything of yours that stores a node id (positions, current_node, overlays,
   corpus references) sees new ids after that save; 832's uid-paired table for its 24 corpus maps is
   `docs/reports/T-1168-node-id-map.md` at tag designer-v0.20.0.
4. **An inherited `FRAMEWORK_ROOT` is honoured only if it holds both `lib/` and `agents/`** (T-4248). A fixture
   that points `FRAMEWORK_ROOT` at a fake tree with only `lib/` now gets re-resolved to the real framework. Give the
   fake tree an `agents/` directory. `fw` warns about a stale inherited value once per shell, never on hook calls
   (T-4298).
6. **`fw` no longer creates a project implicitly** (T-2746). Run with no terminal (an agent's shell, cron, a pipe)
   from a directory that is not an AEF project, `fw <command>` used to run `fw init` there silently; it now exits 1
   with `not in an AEF project: DIR; run fw init …`. A script that relied on the implicit init must call
   `fw init DIR` first.
5. **`git -c key=value …` and other unknown git global options are never read-only** (T-4264). `git -C DIR status`
   and `git --git-dir=X log` are now read-only like their bare forms; anything with `-c` goes through the task gate.

## Behaviour changes you will notice

- **CLAUDE.md upgrade refuses instead of silently deleting your lines** (T-4232, G-117). If you added lines inside a
  framework-managed governance section, `fw upgrade` step [1/10] now stops, leaves CLAUDE.md byte-identical, and names
  each line it would have removed. Wrap your own lines in `<!-- project-owned: begin -->` /
  `<!-- project-owned: end -->` and re-run; marked regions survive every upgrade verbatim.
- **Watchtower no longer opens the firewall by itself** (T-4297, security). A loopback bind never touches the
  firewall. A LAN bind changes it only with `fw config set WATCHTOWER_OPEN_FIREWALL 1`; otherwise it prints the exact
  `sudo ufw allow PORT/tcp` command. Before this release, `watchtower start` added a rule open to Anywhere even for a
  127.0.0.1 bind: check `sudo ufw status` and remove any rule you did not intend.
- **Watchtower checks its Python modules before starting** (T-4304). On a clean machine without `markdown2` (or
  another required module) it exits with one line naming the modules and the install command for your OS, instead
  of a traceback. It never runs sudo or pip for you.
- **A `bin/fw` that does not parse no longer takes every hook down** (T-4303, G-118). Hooks route before the bulk of
  `bin/fw` is read, and the error names `bin/fw` and the repair (`bash -n bin/fw`, `git diff bin/fw`).

## Before you commit the upgrade

- **Check the vendored patches.** If you keep local patches under `.agentic-framework/`, list them in
  `.fwvendor-preserve.yaml` and merge upstream changes by hand (T-4233 will automate the 3-way merge).
- **Check nothing foreign is staged.** `git diff --cached --name-only -- .tasks .context/episodic` must be empty
  before your first commit after the upgrade (G-114).

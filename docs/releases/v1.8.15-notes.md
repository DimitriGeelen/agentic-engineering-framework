# v1.8.15

v1.8.15 is the broad release that follows the v1.8.14 security hotfix. It carries about 1,890 commits from the
`bleeding-edge` branch since v1.8.14. Most of them are fixes to upgrades, the governance gates, TermLink workers and
Watchtower, many of them reported by the projects that use the framework.

It was field-tested on pre-release tags `v1.8.15-be.1` to `be.51` from 2026-10-20 to 2026-10-29. The last round ran
under a release freeze: no new development, only testing and fixing what testers reported broken. Four testers
upgraded cleanly to be.50, two of them also to be.51, and 1409-sprind ran its full suite on be.50 with no new reds.
Since the release, five projects have upgraded to the v1.8.15 tag itself with nothing broken: dimitri-mint-dev,
832, ring20-dashboard, 055 and 0506.

If you are on v1.8.14 or earlier, upgrade. Read **Behaviour changes** and **Known issues** first.

## Highlights

**Upgrades and vendoring**
- `fw upgrade` no longer changes its own source. A refused upgrade no longer vendors first, and a framework clone
  used as the upgrade source stays byte-identical (**T-4498**, **T-4688**).
- A shallow source is unshallowed by the upgrade itself instead of being refused (**T-4235**). Upgrading through a
  tag clone inside the consumer tree, or through a linked worktree, uses that copy and pins its commit (**T-4680**,
  **T-4661**).
- The upgrade summary now lists the files it left for you to commit, with one `git add` line (**T-4692**, **T-4697**,
  **T-4705**, **T-4712**, **T-4717**, **T-4723**, **T-4724**). Tracked runtime files are grouped by directory with one
  exact `git rm --cached` command (**T-4701**, **T-4754**).
- `fw vendor` writes only files that changed, so a repeat upgrade no longer rewrites unchanged files or makes
  Watchtower look stale (**T-4720**, **T-4740**).
- `fw upgrade` re-installs the pinned Workflow Designer where one was installed, and removes superseded designer
  builds (**T-4672**, **T-4736**).
- `install-hooks` never comments out or drops a consumer's own hook lines (**T-4515**, **T-4678**).

**Governance gates and the read-only allowlist**
- Many commands that could write a file or run code while passing as a read are now refused without a task: awk
  `system()` and pipes, sed `e`, process substitution, `git grep -O`, `sort --compress-program`, `rg --pre`,
  `git fetch --upload-pack`, `git help -w` and more (**T-4509** … **T-4513**, **T-4626** … **T-4631**).
- Plain reads that were over-blocked are admitted again, for example `sed -n` on a glob file operand (**T-4650**).
- Gate messages name the real part of a command that was refused (**T-4827**).

**TermLink workers and sessions**
- Worker environments are built by construction: inherited `FW_*` variables no longer leak into workers, TermLink
  variables are allow-listed by name, and PATH is constructed rather than copied (**T-4647**, **T-4659**,
  **T-4665**, **T-4666**).
- `claude-fw` runs one tmux server per project, and `fw doctor` warns on a shared server (**T-4781**).
- Dispatch worker directories live under the project, in `.context/dispatch` (**T-4675**). The first dispatch to a
  codex, opencode or antigravity seat no longer fails with "would shadow" (**T-4683**).
- `fw termlink cleanup` is scoped to the project and keeps uncollected results (**T-4558**).

**Sidecar peer messaging**
- `fw sidecar alerts` lists unanswered DM mail addressed to this project, including any keys in the new
  `SIDECAR_DM_ADDRESS_KEYS` setting (**T-4880**, **T-4881**).
- `sidecar start` and `stop` refuse when an inherited `PROJECT_ROOT` names a different project (**T-4753**).
- A sender can settle its own outstanding consult with `fw sidecar settle-sent` (**T-4757**).

**Watchtower and the Workflow Designer**
- `/designer` opens the designer's project browser. The framework's own card list moved to `/designer/corpus`
  (**T-4716**, **T-4718**).
- The pinned designer moved from 0.23.0 to 0.31.0 in steps, and its validator is delivered to consumers
  (**T-4448**, **T-4633**, **T-4732**, **T-4764**, **T-4767**, **T-4838**, **T-4836**).
- New endpoints for the designer: `POST /api/validate`, `GET /api/instances` and `GET /api/field-catalog`
  (**T-4830**, **T-4845**, **T-4831**, **T-4832**).
- Watchtower defers to a systemd-managed Watchtower when one exists (`WATCHTOWER_ENSURE`), and runs in its own
  scope (**T-4706**, **T-4711**). `/search` no longer returns 500 while its index rebuilds (**T-4458**).
- The key store accepts an Anthropic key (**T-4742**, **T-4749**).

**Audit, pre-push and the unit-suite ratchet**
- Pre-push names which process holds the audit lock, and scheduled audits yield to a waiting push (**T-4542**).
- The pre-push `retire_when` check searches tracked files instead of walking the project root. On one tester's
  project a push went from 5–6 minutes to 14 seconds (**T-4891**).
- The unit-suite ratchet retries a newly red test file once. A pass on retry is graded WARN as suspected flaky
  (**T-4875**).
- `fw doctor` is faster (from about 199 s to about 60 s, **T-4386**), and `fw task create` no
  longer forks per task file (**T-4797**).

**Session restart and continuous mode**
- `claude-fw -c` resumes this session's own conversation, never a worker's (**T-4497**).
- Disarming continuous mode is recorded as a disarm, not a termination, and the stop driver leaves dispatched
  workers alone (**T-4806**, **T-4750**).

**Release and issue handling**
- Release and pre-release tags are pushed to every remote and read back (**T-4673**). Pre-release `-be` tags never
  count as the latest release (**T-4431**).
- Submitter replies on GitHub issues are read: a confirmation closes a fixed issue, and `fw issues reply-ack` settles
  a reply that needs no action (**T-4660**, **T-4668**, **T-4669**).

Internal work, briefly: many test-isolation and flake fixes, a local backend for the shared worker contract
(**T-4802**), and the `fw runme` job queue (**T-4491** … **T-4493**).

## Behaviour changes to know about

- **Some commands now need a task.** The read-only allowlist refuses more command shapes (see Highlights). If a
  command you used as a read is now blocked, start a task or use a plain form.
- **Writes to `.git/config`, `.git/info/attributes` and `.git/hooks/` need a task** (**T-4639**).
- **`tmux kill-server` and `tmux kill-session` without `-S` or `-L` are refused**, so one project cannot kill
  another project's tmux server (**T-4783**).
- **The degraded boundary gate** (used when its normal checker cannot run) refuses writes under system directories
  such as `/etc` and `/usr`, quoted or not (**T-4852**, **T-4872**).
- **`/designer` moved.** It now opens the designer's project browser; the old gallery is at `/designer/corpus`.
  If your own tests point at `/designer`, update them (832 had to) (**T-4716**).
- **New gitignore entries.** `fw init` and `fw upgrade` ignore runtime state under `.context/working/` and the new
  `.context/dispatch/` directory (**T-4231**, **T-4684**, **T-4689**, **T-4747**).
- **Consumer `CLAUDE.md` now carries the Worktree Policy** (worktrees are opt-in only) (**T-4833**). If your project
  has its own rule on worktrees, check that the two agree.
- **Reviewer auto-ticks are stricter.** A `[REVIEWER]` criterion is ticked only when it names a check the scan ran
  and that check found nothing. Expect fewer automatic ticks (**T-4778**).
- **`claude-fw` and TermLink workers run in a systemd scope** outside the login session, where systemd is available
  (**T-4636**).
- **Upgrade next steps** name your focused task, not a fixed example id (**T-4704**).

| 0506 | v1.7.832 straight to v1.8.15; the upgrade restored its missing sidecar hooks and peer messages now show their text (**T-4884**) |

Earlier rounds also had reports from 050-email-archive.

**The confirmation rule** (operator, 2026-10-28):
- A clean full upgrade by at least three different testers (`fw doctor` no worse, their own tests as before, the
  project still works) confirms consumer-facing changes that have no specific verdict.
- A fix that was specifically tested and FAILED must be fixed and re-confirmed.

Under that rule, three clean be.50 upgrades (dimitri-mint-dev, ring20-dashboard, 832) confirmed the be.50 fixes,
with ring20 as a fourth. T-4891, added in be.51, was confirmed on be.51.

**After the release**, dimitri-mint-dev, 832, ring20-dashboard, 055 and 0506 upgraded to the v1.8.15 tag. In each, the
upgrade exited 0 and doctor had no new FAIL. Their own tests were unchanged (055: 1707 passed; 832: 215 passed;
ring20-dashboard: about 17,000 passed).

**Found by testers and fixed before release** (a selection):
- **T-4872**: the degraded boundary gate missed a quoted system path (ring20-dashboard FAILS on T-4852). Fixed and
  confirmed.
- **T-4873**: an audit exemption applied while continuous mode was still armed (055 FAILS on T-4809). Fixed and
  confirmed.
- **T-4891**: pushes took minutes on a project in a home directory. Fixed and confirmed.
- **T-4683**: the first dispatch to a non-Claude review seat failed live (ring20 FAILS on T-4675).
- **T-4723**, **T-4724**: the upgrade file list ran out of memory on a home-directory consumer and printed in the
  wrong place.
- **T-4740**: a repeat upgrade still rewrote the designer build and vendor metadata (ring20 PARTIAL on T-4720).
- **T-4845**: `POST /api/validate` reported a successful check as a failure (832 FAILS on T-4830).

## Known issues

- **T-4870: an upgrade can drop a protected local edit inside a vendored file.** 1409-sprind had a small block in a
  vendored file that registered their own Watchtower page. The upgrade removed it without a warning (the page file
  itself was kept). After upgrading, check your local edits in vendored files and re-apply any that are missing.
- **T-3297: a push can be refused while a scheduled audit holds the audit lock.** The pre-push gate waits for a
  limited time and then refuses with "audit COULD NOT RUN (another audit holds the lock) … This is not an audit
  failure". Push again when the scheduled audit has finished.
- **T-4896: `unit-suite.sh` run by hand without `FW_UNIT_SUITE_DIR` runs nothing.** In a consumer it reports success
  and overwrites `LATEST.yaml` with an empty result. Always pass `FW_UNIT_SUITE_DIR` when you run it by hand.

## Upgrading

Upgrade from a **non-shallow** clone of the tag. Run a dry run first:

```
git clone --branch v1.8.15 https://github.com/DimitriGeelen/agentic-engineering-framework.git <dir>
<dir>/bin/fw upgrade /path/to/project --dry-run
<dir>/bin/fw upgrade /path/to/project
```

Then, in your project:

1. Run `fw doctor`. Compare it with your reading from before the upgrade.
2. If doctor says the Watchtower process predates its own source, run `fw watchtower restart`.
3. Commit the files the upgrade summary lists.
4. Restart your Claude session, so the new hooks load.
5. Check any local edits you keep inside vendored files (see T-4870 above).

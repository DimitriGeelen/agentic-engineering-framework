# v1.8.12 — security hotfix

v1.8.12 is v1.8.11 plus two fixes. Both close gaps where the framework's read-only command allowlist let an agent run
something that is not a plain read inside the project. Nothing else changed. If you are on v1.8.11, upgrade.

## Fixes

**T-4343: `git -C`, `--git-dir` and `--work-tree` outside the project are no longer treated as read-only.**
In v1.8.11 (from T-4264), `git -C /some/other/repo status` and the `--git-dir`/`--work-tree` forms passed the task
gate as reads. A repository's own config (core.fsmonitor, core.pager, diff.external, filters) can run arbitrary
commands, so a "read" of a repository outside the project can execute code.
- A value resolving (realpath) inside the project root stays read-only.
- These are gated: outside paths, `..` escapes, symlinks pointing out, and quoted, variable, `~`, glob or
  unresolvable values.
- Relative values resolve against a leading `cd X &&`, and repeated `-C` values resolve cumulatively, as git does.

**T-4344: the boundary read scanner no longer skips the word after a flag that takes no value.**
In v1.8.11 (from T-4284), `git diff --no-index -m /etc/shadow` and `git log --summary /etc/shadow` hid the outside
path. The scanner now knows which options take a free-text value, per command and subcommand.

## How it was tested

- **Regression tests:** `tests/unit/t4343_git_repo_path_boundary.bats` and
  `tests/unit/t4344_boundary_read_free_text_opts.bats`. The T-4343 file fails 26 of 40 cases on v1.8.11 and passes
  all of them on v1.8.12.
- **Field test:** ring20-dashboard, the project that reported both issues, ran the hotfix. Every case WORKS.
- **Full unit suite, v1.8.12 vs v1.8.11** (same host, same start time, clean env): 66 failing tests against 71, and
  0 failures attributed to the hotfix diff. The one hotfix-only failure and two hotfix-only timeouts all pass when
  run alone, and none of them exercises the changed files.

Evidence: `docs/reports/T-4345-hotfix-v1812.md`.

## Why it was released

Under the standing release rule, a fix ships to master when it has a positive field test and the release's own gates
are green. Both fixes have both. The release decision is recorded in `.context/releases/decisions.jsonl`
(`v1.8.12`, by field-evidence).


"Upgrading from v1.8.10".

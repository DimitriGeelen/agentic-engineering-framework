## Behaviour changes

**Watchtower listens on this machine only by default (T-4239, GitHub #103).** Watchtower has no
login, and it can tick Human criteria and record decisions. Until now a fresh start with nothing
configured listened on every network interface (`0.0.0.0`). The default `HOST` is now `127.0.0.1`.

- If you open Watchtower from another machine, run once in your project:
  `fw config set HOST 0.0.0.0 && fw watchtower restart`
  (or set `HOST` to one specific address).
- An instance that is already running keeps its address when restarted (see the next item), so a
  Watchtower that listens on `0.0.0.0` today changes only at its next fresh start, for example after a
  reboot. `fw doctor` then prints the command above.

**`fw watchtower restart` keeps the running address (T-4360, GitHub #103).** A restart from a shell
without `FW_HOST` (an agent session, for example) used to come back on the default, which silently
widened a Watchtower bound to one address to every interface. Restart now reuses the running address,
unless `FW_HOST` or `HOST` is set explicitly; when that widens to `0.0.0.0` it prints a warning.

## Fixes

- **Task files stay readable for other accounts (T-5077, reported by 832).** `fw task update` and every
  other in-place edit left the edited file at mode 0600, which also removed access granted through an
  ACL. Edits now keep the file's mode, owner and ACL. If another account lost access to your task
  files, reset them once: `find .tasks -name '*.md' -perm 600 -exec chmod 0664 {} +`
- **`fw doctor` can be told a component is left out on purpose (T-4355, GitHub #98).** List optional
  components in `ABSENT_COMPONENTS` (for example `fw config set ABSENT_COMPONENTS "termlink node"`);
  `fw doctor` then shows OK "absent by choice" instead of a warning. A component a workflow needs still
  warns, and a misspelled name warns.
- **`[OPERATOR]` for criteria in any language (T-4359, GitHub #102).** Criteria only the operator may
  close were recognised by English words only. Start a Human criterion with `[OPERATOR]` and it always
  goes to the operator, whatever the language.
- **`watchtower stop` no longer reports a false "Failed to stop" (T-5078).** The liveness check read a
  process its parent had just cleaned up as still alive.
- **Generated release files do not withdraw reviewer approvals (T-5079, proposed by 832).** List the
  folders your release generates in `RELEASE_ARTIFACT_PATHS` (committed in `.framework.yaml`); a release
  commit that touches only those leaves the reviewer's approvals standing. Entries that would cover
  source are refused and reported by `fw audit`.
- **`lib/costs.sh` loads correctly without `FRAMEWORK_ROOT` (T-5076)**, found by running the unit suite
  on a second machine.

Reported by Mehdi (GitHub #107–#113 and the #98 follow-up), fixed after be.47:

- **Onboarding tasks of an existing project can be closed (T-5087, #107).** T-002 to T-006 had no
  `## Updates` section, so the first status entry landed inside `## Verification` and the close was
  refused. The seeds have the section now, and a task file that lacks it gets one instead of an entry
  glued onto its last section. Projects already initialised: add `## Updates` at the end of those five
  tasks and move any entry that sits under `## Verification` into it.
- **`fw fabric register` says what it left unfilled (T-5088, #108)** instead of "REFUSED" when it did
  write the card.
- **Dotfiles get their own component cards (T-5089, #109).** `.gitignore` becomes `dot-gitignore`, so it
  no longer collides with `gitignore`; existing cards are still recognised.
- **`mcp` and `cryptography` are declared (T-5090, #110)** in `web/requirements.txt`. Without `mcp`, the
  `fw` MCP server now says which package to install instead of exiting with a traceback.
- **A quoted grep pattern is not taken for a path (T-5091, #111).** `grep -rE '/home/|192\.168\.' docs/`
  is no longer refused as an outside read. Only the pattern of grep/egrep/fgrep/rg is exempt, and only
  when the command's options are understood; file operands, `-f FILE` and `--exclude-from FILE` are
  judged as before.
- **A `>` inside quotes is not a file write (T-5092, #112).** `awk -F: '$2>9' notes.txt` is no longer
  refused by the task gate. Quoted text that can run (`sh -c`, `eval`, perl/python, an awk `print > f`,
  `"$(...)"`) still counts as a write.
- **The consumer `CLAUDE.md` template describes `fw handover` correctly (T-5093, #113):** it commits and
  pushes by default; use `--no-commit` to fill the `[TODO]` sections first.
- **Playwright can be declared absent by choice (T-5095, #98).** `ABSENT_COMPONENTS=playwright` turns both
  Playwright warnings in `fw doctor` (pip package, MCP server) into "absent by choice".
- **Issue tracking (T-5094, T-5096):** a submitter's confirmation is recognised when it comes after the
  test details, and a second fix on the same issue can be announced.

## Behaviour changes (continued)

**Your last tick hands a task back to the agent (T-5081, proposed by 832).** When the operator ticks the
last open Human check of a task in Watchtower, the task's owner becomes the agent, which then closes it;
this is the rule an AI reviewer's approval already followed. Unticking a check on a task waiting for
review hands it back to the operator.

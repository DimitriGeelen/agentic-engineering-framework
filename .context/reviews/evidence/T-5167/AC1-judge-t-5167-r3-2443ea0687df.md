## What I checked

1. **Landing page arc cards** (01-root.png, landing@1024/1440/1920.png, live fetch of `/`).
   The "Arcs in flight" card lists 19 arcs, each a link `/tasks?arc=arc-NNN`, each with a
   non-zero task count. At all three widths every row shows id, name and count, nothing
   clipped, overlapping or hidden.

2. **Clicking a card** (real Chromium click at 1440, my own run; click-arc-012.png).
   - arc-012 (card: 53 tasks) → `/tasks?arc=arc-012`, heading "Tasks 53", filter chip
     "arc: arc-012", board columns 1 + 0 + 5 + 0 + 47 = 53, cards badged arc-012.
   - arc-011 (card: 52) and arc-002 (card: 3) → likewise open their filtered view with the chip.
   - No console or page errors.
   Before the fix these links opened an empty list (task RCA); they are now non-empty.

3. **Every card link, live** (curl of each of the 19 links with `&view=list`, distinct task rows
   compared with the count on the card): 17 of 19 equal the card count exactly. The other two
   list ONE MORE task than the card says, and in both the list is right about membership:
   - arc-019: list 20, card 19. Extra is T-3147, which carries the tag
     `arc:ewcr-arc0-contract-evidence` on a wrapped second line of its `tags:` list; the
     card's file scanner reads only the first line.
   - arc-003: list 124, card 123. Extra is T-1717, tagged `arc:orchestrator-rethink` in its
     episodic record (.context/episodic/T-1717.yaml), which the task list merges in and the
     card count does not.
   No card opened an empty list or another arc's list. The default (board) view shows fewer
   cards than the count for large arcs because the Completed column is capped with a
   "+N more →" link to the same filtered list; the heading count is the full number.

4. **Slug vs id comparison** (02-…arc-grooming.png, 03-…arc-005.png, list-by-slug/list-by-id
   at 1024/1440/1920, and live fetch).
   `/tasks?view=list&arc=arc-grooming` and `/tasks?view=list&arc=arc-005`: 52 distinct tasks
   each, the two id sets byte-identical (`cmp`), T-1846 … T-3508. Screenshots show "Tasks 52"
   and the chip "arc: arc-grooming" / "arc: arc-005" at every width, same rows in the same
   order. `?arc=no-such-arc` lists 0 tasks (an unknown name does not list everything).

5. **Code and tests.** `arc_identities()` resolves id or slug from `.context/arcs/*.yaml`;
   the filter passes both names to `task_dict_in_arc`. `pytest
   tests/unit/test_t5167_arc_filter_both_names.py`: 5 passed (my run).

6. **04-tasks.png** (unfiltered `/tasks`): board renders normally, 5156 tasks, no regression visible.

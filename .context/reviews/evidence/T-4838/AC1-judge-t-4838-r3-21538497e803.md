## Method
I drove the live page http://192.168.10.107:3000/designer/app in headless Chromium (Playwright, 1600x1400). Nothing was saved: Save and Save to project were never pressed.

1. The page loads and the header reads **v0.31.0** (the bundle has `const APP_VERSION = '0.31.0'`). The map "investigate" is open by default.
2. I selected the step **Write report** (frw_2_write). Under I/O CONTRACT, I opened "edit attributes" on output[0] **report_path**, set `operation` to **update** and added no match field. The other options were read/create/update/upsert/delete.
3. I pressed **✓ Check**. The page sent a POST to /api/validate, which returned ok:true.

## Result
- **Validate endpoint** (captured from the network): one finding,
  `{rule: E-XML-IO-MATCH-MISSING, severity: ERROR, location: node 'frw_2_write' output[0] "report_path", message: operation="update" with no aef:field role="match": the map reads as update every instance; name the field that picks the instance}`
- **Designer**: a `.io-finding` block (data-rule=E-XML-IO-MATCH-MISSING, data-sev=ERROR) appears directly under the report_path output row and above its attribute editor. It shows the severity, the message and the rule id. The text is the same as the endpoint's, so the designer and the endpoint agree.
- The validator dock reads "1 finding · 1 error, 0 warnings · 1 on the map" and lists the same row. The Write report node carries a canvas marker.
- The second output (audit_entry) and both inputs have no finding block, so the finding sits on the correct row only.
- **Legibility**: on the input rows (findings/ref, run_id/string) the green-checked "req" and the "×" are clearly readable. The output rows' "×" is readable too. See io-row-zoom-judge-t-4838-r3-21538497e803.png.

## Timings (click to content ready)

|------------|------|
| nav /fabric → /bvp (two runs) | 5.71 s, 5.15 s |
| direct load of /bvp | 2.76 s (server alone: 3.28 s for 820 KB via curl) |
| nav /bvp → /terminal (two runs) | 0.44 s, 0.38 s (direct: 0.19 s) |
| nav → /tasks, fresh browser, from /fabric, /terminal, /settings/ | 0.87 s, 0.51 s, 0.52 s (direct: 0.42 s) |
| nav /tasks → /fabric | 0.74 s, 0.85 s |

One `/terminal → /tasks` swap right after the `/bvp` loads took 5.45 s; it did not reproduce in three fresh-browser runs (0.5 to 0.9 s), so I read it as the server still busy with `/bvp`, not as the handler.

Cause of the `/bvp` time: the handler in `web/templates/base.html:1010-1027` lets htmx fetch the page, sees a script the document has not loaded, cancels the swap and calls `window.location.assign`, which fetches the same page again. For `/terminal` (0.03 s server) that is invisible; for `/bvp` (about 3 s server) it doubles the wait, with nothing on screen in between.

- "ordinary pages switch instantly as before": met (swap kept, 0.5 to 0.9 s).

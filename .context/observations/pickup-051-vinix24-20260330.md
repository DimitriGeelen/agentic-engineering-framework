## BUG-1: Fabric Explorer has hardcoded OpenClaw project data

**Severity:** High — breaks every consumer project
**File:** `web/templates/fabric_explorer.html`
**Lines:** 423-519 (in upstream)

### Problem

The Fabric Explorer template has ~100 lines of hardcoded OpenClaw-specific data:

1. **Line 369:** `<h1>OpenClaw Fabric Explorer</h1>` — hardcoded project name
2. **Lines 423-430:** `const layers` — 6 OpenClaw architectural layers (Entry, Control Plane, Agent Runtime, Extensions, Platform, Infrastructure) with OpenClaw subsystem lists
3. **Lines 432-462:** `const subsystemData` — 29 OpenClaw subsystem descriptions (gateway, channels, ai-providers, plugin-sdk, etc.) with LOC counts, findings, descriptions
4. **Lines 464-488:** `const edges` — OpenClaw subsystem dependency edges
5. **Lines 490-519:** `const subsystemReports` — OpenClaw deep-dive report filenames (T-045 through T-089)
6. **Lines 371-377:** Stats bar hardcoded: "280K LOC", "81 Extensions", "50 Deep-dives", "561 Dep edges", "7 Extracted"

### Root Cause

The template was built for the OpenClaw analysis and the data was never parameterized. When vendored into a consumer project, every project shows OpenClaw's architecture instead of its own.

### Fix Applied in 051-Vinix24

Replaced all hardcoded data with dynamic generation from `componentData` (which is already injected by Flask from `.fabric/components/*.yaml`):

```javascript
// componentData MUST be defined FIRST (was defined AFTER layers/subsystemData — BUG-2)
const componentData = {{ components | tojson }};

// Dynamic layers — one per subsystem with rotating palette
const _palette = ['#6366f1','#06b6d4','#8b5cf6','#10b981','#f59e0b','#64748b','#ec4899','#14b8a6','#f97316','#a855f7','#ef4444','#84cc16'];
const _allSubs = [...new Set(componentData.map(c => c.subsystem).filter(Boolean))].sort();
const layers = {};
_allSubs.forEach((sub, i) => {
  layers[sub] = { color: _palette[i % _palette.length], subsystems: [sub] };
});

// Dynamic subsystemData from components
const subsystemData = {};
_allSubs.forEach(sub => {
  const comps = componentData.filter(c => c.subsystem === sub);
  subsystemData[sub] = {
    name: sub.charAt(0).toUpperCase() + sub.slice(1),
    count: comps.length, loc: '', finding: '',
    desc: comps.slice(0, 3).map(c => c.purpose || c.name).join('; ')
  };
});

// Dynamic edges from component depends_on (subsystem-to-subsystem)
const edges = [];
{
  const seen = new Set();
  componentData.forEach(c => {
    (c.depends_on || []).forEach(dep => {
      const target = componentData.find(t => t.id === dep.target || t.name === dep.target || t.location === dep.target);
      if (target && c.subsystem !== target.subsystem) {
        const key = c.subsystem + '->' + target.subsystem;
        if (!seen.has(key)) { seen.add(key); edges.push([c.subsystem, target.subsystem]); }
      }
    });
  });
}

const subsystemReports = {}; // Empty — no reports yet

// Dynamic stats bar
const nEdges = componentData.reduce((s, c) => s + (c.depends_on || []).length, 0);
const nTags = new Set(componentData.flatMap(c => c.tags || [])).size;
document.getElementById('explorer-stats').innerHTML =
  `<div><span>${nComps}</span> Components</div>` +
  `<div><span>${subs.size}</span> Subsystems</div>` +
  `<div><span>${nEdges}</span> Dep edges</div>` +
  `<div><span>${Object.keys(nTypes).length}</span> Types</div>` +
  `<div><span>${nTags}</span> Tags</div>`;
```

### Recommendation

Apply the same fix to upstream `web/templates/fabric_explorer.html`. The OpenClaw data can be kept as a fallback or removed entirely — the dynamic approach works for ALL projects including the framework itself.

## BUG-2: componentData defined AFTER it's referenced

**Severity:** High — graph renders empty (0 nodes, 0 edges)
**File:** `web/templates/fabric_explorer.html`
**Lines:** 423 vs 462

### Problem

In the template, `const componentData = {{ components | tojson }};` appears AFTER `const layers`, `const subsystemData`, and `const edges` — all of which reference `componentData`. JavaScript hoists `const` declarations but does NOT initialize them, so all dynamic generation silently produces empty objects.

Result: the D3 force graph renders with zero nodes. The dark canvas appears but nothing is drawn.

### Fix

Move `const componentData = {{ components | tojson }};` to be the FIRST constant defined in the `<script>` block, before layers/subsystemData/edges.

## ENHANCEMENT-1: `fw upgrade` should sync web/ directory

**Severity:** Medium — consumer projects get stale Watchtower UI
**File:** `lib/upgrade.sh`

### Problem

`fw upgrade` syncs:
- CLAUDE.md governance sections
- Task templates
- Seed files
- Git hooks
- `agents/context/*.sh` scripts
- `bin/fw` binary
- `.claude/settings.json` hooks
- `.mcp.json` MCP servers
- Version tracking

But it does NOT sync:
- **`web/`** — Watchtower templates, blueprints, static assets
- **`agents/`** — (except context scripts)
- **`lib/`** — shared libraries

This means when the framework gets Watchtower improvements (like the Fabric Explorer), consumer projects running `fw upgrade` don't get them. We had to manually `rsync` the web/ directory.

### Recommendation

Add a step to `fw upgrade` that syncs the full `web/` directory to the vendored copy:

```bash
# [4d/10] Vendored web UI
if [ -d "$vendored_dir/web" ]; then
    if ! diff -rq "$FRAMEWORK_ROOT/web" "$vendored_dir/web" --exclude="__pycache__" > /dev/null 2>&1; then
        rsync -a --delete --exclude="__pycache__" "$FRAMEWORK_ROOT/web/" "$vendored_dir/web/"
        echo -e "  ${GREEN}UPDATED${NC}  Web UI synced"
    else
        echo -e "  ${GREEN}OK${NC}  Web UI current"
    fi
fi
```

Same pattern for `agents/` and `lib/`.

Consider: should `fw upgrade --dry-run` show a diff summary of web/ changes?

## ENHANCEMENT-2: `fw update` fails for vendored installs

**Severity:** Low — `fw upgrade` is the correct command, but error message is confusing
**File:** `bin/fw` (update command handler)

### Problem

## ENHANCEMENT-3: Pass project_name to templates

**Severity:** Low — cosmetic, but improves multi-tenant UX
**File:** `web/shared.py` → `render_page()`

### Problem

`render_page()` passes `project_root` to templates but not `project_name`. Templates that want to show the project name (e.g., base.html ambient strip already shows it) have to derive it from the path.

### Recommendation

Read `project_name` from `.framework.yaml` and pass it in `render_page()`:

```python
# In shared.py, near PROJECT_ROOT definition
_project_name = None
def get_project_name():
    global _project_name
    if _project_name is None:
        fw_yaml = PROJECT_ROOT / ".framework.yaml"
        if fw_yaml.exists():
            import yaml
            data = yaml.safe_load(fw_yaml.read_text())
            _project_name = data.get("project_name", PROJECT_ROOT.name)
        else:
            _project_name = PROJECT_ROOT.name
    return _project_name

# In render_page()
context.setdefault("project_name", get_project_name())
```

Then templates can use `{{ project_name }}` directly. The base.html title could become:
```html
<title>{{ page_title }} — {{ project_name }}</title>
```

## ENHANCEMENT-4: Fabric Explorer subsystem descriptions from subsystems.yaml

**Severity:** Low — nice-to-have for richer subsystem detail panels
**File:** `web/blueprints/fabric.py`

### Problem

The `fabric_graph()` route already loads `_load_subsystems()` from `.fabric/subsystems.yaml`, which contains `summary` and `key_files` per subsystem. But this data isn't passed to the Fabric Explorer template — only the component data is passed.

### Recommendation

Pass subsystem registry data to the template:

```python
# In fabric_graph()
subsystem_registry = {s["id"]: s for s in _load_subsystems()}

return render_page(
    "fabric_explorer.html",
    components=components,
    subsystem_registry=subsystem_registry,  # NEW
)
```

Then in the template, use it to enrich `subsystemData`:
```javascript
const subsystemRegistry = {{ subsystem_registry | tojson }};
// Use registry summary as desc if available
_allSubs.forEach(sub => {
  const reg = subsystemRegistry[sub];
  subsystemData[sub].desc = reg?.summary || subsystemData[sub].desc;
});
```


How to work (framework repo /opt/999-Agentic-Engineering-Framework, branch bleeding-edge, main checkout, no worktree):
1. Run `bin/fw work-on {TASK}` alone on its own line. Read the task file in .tasks/active/{TASK}-*.md (description holds the scope and the evidence).
2. BEFORE any source edit, with the Edit tool: replace the placeholder Agent ACs with real, checkable ones, and write `## Verification` shell lines that would fail before your fix and pass after (gate G-020 blocks source edits until the ACs are real). This is a bug-class task: fill `## RCA` (symptom, root cause with file:line, why nothing caught it, what now prevents recurrence).
3. Localise first (read the code, confirm the root cause with one test). Then fix it, minimal and in the style of the surrounding code.
4. Add a regression test (bats under tests/unit/ or pytest tests/unit/test_*.py, whichever the neighbouring code uses) that fails without the fix. Run it and the existing tests closest to the changed file.
5. If you touched bin/fw, lib/, agents/, policy/, web/ or .tasks/templates/: run `bin/fw vendor self` (new files need FW_VENDOR_ONLY="path1 path2" bin/fw vendor self) and confirm `bin/fw vendor self --check` is clean; add `bin/fw vendor self --check` to ## Verification.
6. Tick each Agent AC with the Edit tool as it becomes true. Run every ## Verification line yourself.
7. Commit ONLY your own paths, named explicitly: `git add <your paths>` then `git commit -m "{TASK}: <what changed>" -- <your paths>` (the `-- <paths>` form commits only those paths even if another worker has staged other files in the shared index; never -A, never a bare commit; for a moved or deleted file name the OLD path too, or HEAD keeps it). If the commit hits index.lock (another worker committing), wait 20 s and retry.
8. Do NOT close the task (no --status work-completed); the parent verifies and closes it.
HOOK SAFETY (G-118): every hook in this session runs bin/fw, so a bin/fw that does not parse blocks you, the parent and the operator. When editing bin/fw or any lib/*.sh it sources: make each Edit self-contained (open and close a block in the SAME Edit, never across two), and run `bash -n bin/fw && bash -n <the lib you edited>` immediately after every such Edit. If it fails, fix or revert that edit (`git checkout -- <file>` loses your edits to it, so prefer fixing) before any other tool call.
BATS ASSERTIONS (T-4398): a `! cmd` that is not the last statement of a bats test is inert (set -e ignores negated pipelines), and the pre-push lint refuses it. Write it as `! cmd || false`. Before closing any task that adds or edits bats tests, run `python3 tools/bats-dead-negation-lint.py tests/` and require "clean".
Constraints: stay inside this task's scope; do not edit other tasks' files; no Tier 0 actions; no worktrees; never write to /tmp/fw-agent-*.
Final reply, under 15 lines: root cause (file:line), the fix, the test added and its result, verification results, commit hash, anything left open.
